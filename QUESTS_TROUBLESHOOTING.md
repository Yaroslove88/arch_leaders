# Решение проблемы с квестами

## Дата: 2026-01-07

## Проблема

После `pnpm prisma migrate reset` квесты не появляются.

## Причина

После `prisma migrate reset` все данные удалились:
- ❌ Entries (записи) - удалены
- ❌ Sessions (сессии анализа) - удалены  
- ❌ Quests (квесты) - удалены

**Квесты создаются автоматически** только после анализа сессий!

## Как создаются квесты

### Процесс создания квестов:

1. **Создание Entry (записи)**
   - Пользователь создает запись через `/entries/new`
   - Или через синхронизацию файлов `/sync/entries`

2. **Анализ Entry → Session**
   - Автоматически запускается анализ через LLM
   - Создается Session с:
     - `ability_signals` - сигналы способностей
     - `focus` - точки фокуса
     - `themes` - темы

3. **Генерация квестов**
   - Автоматически вызывается `QuestGenerationService.generateQuestsFromSession()`
   - Создаются квесты на основе:
     - `ability_signals` → квесты на развитие способностей
     - `focus` (high priority) → weekly квесты
     - `themes` → story квесты

## Решение

### Вариант 1: Создать запись и проанализировать (рекомендуется)

1. **Создайте Entry через API:**
   ```bash
   curl -X POST http://localhost:3001/entries \
     -H "Content-Type: application/json" \
     -d '{
       "type": "situation",
       "source": "web",
       "text": "Провел сложную встречу с командой, где нужно было принять решение в условиях неопределенности. Команда была разделена во мнениях, и мне пришлось найти компромисс.",
       "participants": [],
       "tags": []
     }'
   ```

2. **Запустите анализ:**
   - Анализ запускается автоматически при создании Entry
   - Или вручную через `/sync/analyze`

3. **Квесты создадутся автоматически!**

### Вариант 2: Создать тестовые квесты вручную

```bash
curl -X POST http://localhost:3001/quests \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Развить: Контейнирование",
    "description": "Практиковать способность контейнирования в реальных ситуациях",
    "type": "micro",
    "status": "active",
    "criteria": {
      "type": "evidence",
      "target": 3,
      "description": "Собрать 3 доказательства применения способности"
    },
    "reward": {
      "xp": 100,
      "skill_xp": 50
    },
    "linked_nodes": ["node_containment"],
    "tags": ["test"]
  }'
```

### Вариант 3: Использовать синхронизацию файлов

Если у вас есть файлы ситуаций в папке `Лидерство/Ситуации`:

1. **Синхронизировать файлы:**
   ```bash
   curl -X POST http://localhost:3001/sync/entries
   ```

2. **Запустить анализ:**
   ```bash
   curl -X POST http://localhost:3001/sync/analyze
   ```

3. **Квесты создадутся автоматически!**

## Проверка

1. **Проверьте квесты:**
   ```bash
   curl http://localhost:3001/quests
   ```

2. **Проверьте активные квесты:**
   ```bash
   curl http://localhost:3001/quests?status=active
   ```

3. **Проверьте сессии:**
   ```bash
   curl http://localhost:3001/sessions
   ```

## Структура данных

### Quest создается с:
- `title` - название
- `description` - описание
- `type` - micro, weekly, story, in-person
- `status` - active, backlog, done, archived
- `criteria` - критерии выполнения
- `reward` - награда (XP, skill XP)
- `linked_nodes` - связанные узлы способностей
- `session_id` - ID сессии, из которой создан

### Автоматическая генерация:

**Из ability_signals:**
- Тип: `micro`
- Критерий: `evidence` (собрать доказательства)
- Связан с узлом способности

**Из focus (high priority):**
- Тип: `weekly`
- Критерий: `count` (выполнить N действий)
- Фокус на области развития

**Из themes:**
- Тип: `story`
- Критерий: `custom` (создать рефлексии)
- Исследование темы
