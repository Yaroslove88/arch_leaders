## Доступность (Accessibility)

### Критические проблемы 🔴

#### 1. Отсутствие семантических HTML тегов
**Проблема:** Использование `<div>` вместо семантических тегов (`<nav>`, `<main>`, `<section>`, `<article>`)

**Примеры:**
- `Navigation.tsx` - использует `<nav>`, но внутри много `<div>`
- Страницы используют `<div className="min-h-screen">` вместо `<main>`

**Влияние:** Плохая навигация для screen readers, SEO

**Рекомендация:**
```tsx
// Было
<div className="min-h-screen bg-gray-50 p-8">
  <div className="max-w-7xl mx-auto">
    <h1>Заголовок</h1>
  </div>
</div>

// Должно быть
<main className="min-h-screen bg-gray-50 p-8">
  <div className="max-w-7xl mx-auto">
    <h1>Заголовок</h1>
  </div>
</main>
```

#### 2. Отсутствие ARIA атрибутов
**Проблема:** Нет `aria-label`, `aria-describedby`, `aria-live` для интерактивных элементов

**Примеры:**
- Кнопки без текста (только иконки) не имеют `aria-label`
- Модальные окна не имеют `aria-modal="true"`
- Формы не имеют `aria-required` для обязательных полей

**Влияние:** Пользователи screen readers не понимают назначение элементов

#### 3. Управление фокусом
**Проблема:** 
- При открытии модальных окон фокус не переходит внутрь
- При закрытии модальных окон фокус не возвращается к триггеру
- Нет видимого индикатора фокуса для некоторых элементов

**Влияние:** Плохой опыт для пользователей клавиатуры

#### 4. Контрастность цветов
**Проблема:** Некоторые цветовые комбинации могут не соответствовать WCAG AA

**Примеры:**
- `text-gray-500` на `bg-gray-50` - контрастность может быть недостаточной
- `text-blue-600` на белом - нужно проверить

**Рекомендация:** Использовать инструменты проверки контрастности (WebAIM Contrast Checker)

### Средние проблемы 🟡

#### 5. Альтернативный текст для изображений
**Проблема:** В проекте нет изображений, но если появятся - нужно добавить `alt` атрибуты

#### 6. Заголовки
**Проблема:** Некоторые страницы имеют несколько `<h1>`, что нарушает иерархию

**Пример:** `dashboard/page.tsx` имеет `<h1>` и несколько `<h2>`, что правильно, но нужно проверить все страницы

## Навигация и структура

### Сильные стороны ✅
- Понятная структура навигации
- Логичная иерархия страниц
- Использование Next.js Link для клиентской навигации

### Проблемы ⚠️

#### 1. Мобильная навигация отсутствует 🔴
**Проблема:** Навигация скрыта на мобильных устройствах (`hidden sm:flex`)

**Файл:** `Navigation.tsx:24`

```tsx
<div className="hidden sm:ml-6 sm:flex sm:space-x-8">
```

**Влияние:** На мобильных устройствах пользователи не могут перейти к другим разделам

**Рекомендация:** Добавить hamburger меню для мобильных устройств

#### 2. Активное состояние ссылок
**Проблема:** Нет визуального индикатора текущей страницы в навигации

**Рекомендация:** Добавить активное состояние для текущей страницы

```tsx
import { usePathname } from 'next/navigation';

const pathname = usePathname();
<Link 
  href="/dashboard" 
  className={pathname === '/dashboard' ? 'text-blue-600 font-semibold' : 'text-gray-500'}
>
```

#### 3. Breadcrumbs отсутствуют
**Проблема:** На страницах детального просмотра нет breadcrumbs

**Пример:** `/quests/[id]`, `/sessions/[id]`, `/entries/[id]`

**Влияние:** Пользователям сложно понять, где они находятся и как вернуться назад

#### 4. Кнопка "Назад"
**Проблема:** Используется `router.back()`, что может привести на внешний сайт

**Рекомендация:** Использовать явные ссылки или проверять историю

## Визуальный дизайн

### Сильные стороны ✅
- Единая цветовая палитра (синий, фиолетовый, зеленый, серый)
- Использование Tailwind CSS для консистентности
- Хорошие отступы и spacing

### Проблемы ⚠️

#### 1. Типографика
**Проблема:** 
- Нет четкой типографической шкалы
- Размеры шрифтов не систематизированы
- Отсутствует `line-height` для читаемости

**Рекомендация:** Создать типографическую систему в `tailwind.config.js`

```js
theme: {
  extend: {
    fontSize: {
      'xs': ['0.75rem', { lineHeight: '1rem' }],
      'sm': ['0.875rem', { lineHeight: '1.25rem' }],
      'base': ['1rem', { lineHeight: '1.5rem' }],
      'lg': ['1.125rem', { lineHeight: '1.75rem' }],
      'xl': ['1.25rem', { lineHeight: '1.75rem' }],
      '2xl': ['1.5rem', { lineHeight: '2rem' }],
      '3xl': ['1.875rem', { lineHeight: '2.25rem' }],
    }
  }
}
```

#### 2. Визуальная иерархия
**Проблема:** 
- Все карточки выглядят одинаково
- Нет различия в важности элементов
- Отсутствуют визуальные акценты

**Рекомендация:** 
- Добавить тени разной интенсивности
- Использовать разные размеры для важных элементов
- Добавить иконки для категоризации

#### 3. Цветовая система
**Проблема:** Цвета используются интуитивно, нет системы

**Рекомендация:** Создать цветовую палитру в `tailwind.config.js`

```js
colors: {
  primary: {
    50: '#eff6ff',
    100: '#dbeafe',
    // ...
    600: '#2563eb',
    // ...
  },
  success: { /* ... */ },
  warning: { /* ... */ },
  error: { /* ... */ },
}
```

#### 4. Spacing система
**Проблема:** Используются разные значения отступов без системы

**Рекомендация:** Использовать консистентные значения (4, 8, 12, 16, 24, 32, 48, 64)

## Формы и интерактивность

### Сильные стороны ✅
- Валидация на клиенте (required, minLength)
- Визуальная обратная связь при загрузке
- Отключение кнопок во время отправки

### Проблемы ⚠️

#### 1. Использование alert() и confirm() 🔴
**Проблема:** Нативные диалоги не соответствуют дизайну приложения

**Файлы:**
- `quests/page.tsx:35` - `confirm('Завершить квест?')`
- `entries/new/page.tsx:35` - `alert('Ошибка при создании записи')`
- `evidence/page.tsx:55` - `alert('Ошибка при создании доказательства')`

**Влияние:** Плохой UX, нельзя стилизовать, блокируют весь интерфейс

**Рекомендация:** Создать компонент `ConfirmDialog` и `Toast` для уведомлений

#### 2. Валидация форм
**Проблема:** 
- Валидация только HTML5 (required, minLength)
- Нет валидации в реальном времени
- Нет отображения ошибок валидации

**Рекомендация:** 
- Использовать библиотеку (react-hook-form + zod)
- Показывать ошибки под полями
- Валидация на blur и submit

#### 3. Обратная связь при ошибках
**Проблема:** Ошибки показываются через `alert()` или только в консоли

**Рекомендация:** Создать систему уведомлений (Toast)

#### 4. Автосохранение
**Проблема:** Длинные формы (например, создание записи) не сохраняются автоматически

**Рекомендация:** Добавить автосохранение в localStorage

#### 5. Клавиатурные сокращения
**Проблема:** Нет поддержки клавиатурных сокращений (Ctrl+S для сохранения, Escape для закрытия модальных окон)

**Рекомендация:** Добавить обработчики клавиатуры
