# Дополнение теории квестов

> **ВАЖНО:** 
> - **Контентная база:** `QUESTS_STRUCTURED_CONTENT.md` и `QUESTS_THEORIES_MAPPING.md` являются источниками истины для всех данных квестов
> - **Методология:** Этот документ подчинен структуре из `docs/QUEST_CONTENT_STRUCTURE.md` и примерам из `docs/QUEST_THEORY_EXAMPLES.md`
> - **Источник теорий:** Все теоретические блоки находятся в `QUESTS_THEORIES_MAPPING.md`

## Задача

Теоретические блоки (`theory_and_examples`) для всех квестов находятся в:
- **`QUESTS_THEORIES_MAPPING.md`** — полный маппинг всех теорий (контентная база)
- **`data/quest-templates.json`** — JSON-версия (синхронизируется с MD файлами)

При необходимости обновления теории:
1. Обновите `QUESTS_THEORIES_MAPPING.md`
2. Обновите `data/quest-templates.json` (вручную или через скрипт)
3. Синхронизируйте с БД через API

**Структура квеста:**
```json
{
  "id": "micro_контейнирование_напряжения_1",
  "title": "Контейнирование напряжения",
  "description": "...",
  "type": "micro",
  "steps": [...],
  "criteria": {
    "type": "custom",
    "items": [...],
    "theory_and_examples": "ЗДЕСЬ НУЖНА ТЕОРИЯ"  // ← Этот блок нужно дополнить
  }
}
```

## Структура блока "Теория и примеры" (theory_and_examples)

Согласно `docs/QUEST_CONTENT_STRUCTURE.md`, блок `theory_and_examples` содержит:

**Что здесь:**
- Теоретическое объяснение концепции
- Что это значит на практике
- Конкретные примеры применения
- Практические советы
- Как интегрировать в ежедневную практику
- Сравнения и различия (например, "Контроль" vs "Удержание сцены")

**Формат:**
- Markdown текст
- Поддержка заголовков, списков, жирного, курсива
- Может содержать примеры, сравнения, практические советы

**Чего НЕ должно быть:**
- ❌ Шагов выполнения (они в отдельной секции `steps`)
- ❌ Критериев (они в отдельной секции `criteria.items`)
- ❌ Краткого описания цели (оно в `description`)

### Детальная структура теории

Каждый блок `theory_and_examples` должен содержать **детальное объяснение способности** в формате Markdown со следующими разделами:

#### 1. **Детальное объяснение способности**
- Что это за способность в контексте **архитектурного лидерства**
- Почему она критична для развития лидера (обоснование важности)
- Как она связана с переходом от управленца к архитектору
- Какое место занимает в вертикальном развитии (реактивность → интеграция → архитектура)
- Как она связана с другими способностями в курсе

#### 2. **Пояснение терминов**
- Объясни все ключевые термины, используемые в квесте
- Что они означают в контексте архитектурного лидерства
- Как они отличаются от обыденного понимания
- Пример: "Контейнирование — это способность удерживать напряжение, не гася его сразу и не убегая от него. Это не значит 'терпеть' или 'игнорировать', а значит — удерживать в сознании без немедленной реакции."

#### 3. **Обоснование важности**
- Почему эта способность важна именно сейчас (в современном контексте VUCA-мира)
- Какие проблемы она решает
- Что происходит, когда этой способности не хватает
- Как она влияет на эффективность лидера
- Связь с научной базой (Complexity Leadership Theory, Self-Determination Theory, Bion и т.д.)

#### 4. **Связь с методологией курса**
- Как эта способность связана с концепциями курса:
  - **Субъектность** (действие из себя, независимо от инструкций)
  - **Контейнирование напряжения** (Bion, Systems Psychodynamics)
  - **Различение** (факты/интерпретации, роли, уровни)
  - **Сборка форм** (создание целого без разрушения различий)
  - **Системное мышление** (Complexity Leadership Theory)
  - **Вертикальное развитие** (Kegan, Torbert)
- Какие научные теории и исследования её поддерживают

#### 5. **Примеры применения**
- 2-3 конкретных примера ситуаций из практики лидерства
- Как способность проявляется в реальных ситуациях
- Примеры "хорошо" и "плохо" (что происходит с/без этой способности)
- Примеры из разных контекстов:
  - Работа с командой
  - Принятие решений в неопределенности
  - Работа с напряжением и конфликтами
  - Управление изменениями

#### 6. **Практические советы**
- Как начать развивать эту способность
- С чего начать, если это новая способность
- Как заметить прогресс
- Что делать, если не получается
- Типичные ошибки и как их избежать

### Важные требования

❌ **НЕ ДУБЛИРУЙ:**
- Информацию из шагов выполнения (`steps`) — она уже описана отдельно
- Критерии успеха (`criteria.items`) — они уже перечислены

✅ **ФОКУС НА:**
- Объяснении **"ПОЧЕМУ"** и **"КАК"**, а не на "ЧТО делать" (это в шагах)
- Связи с методологией архитектурного лидерства
- Пояснении терминов и концепций
- Обосновании важности способности
- Конкретных примерах из практики

### Методологическая основа курса

При написании теории опирайся на:

1. **Архитектурное лидерство:**
   - Переход от управленца к архитектору сцепок
   - Создание среды, а не контроль
   - Лидер как создатель форм и связей

2. **Ключевые концепции:**
   - Субъектность: действие из себя, осмысленно, независимо
   - Контейнирование (Bion): удержание напряжения без гашения
   - Различение: видение различий (факты/интерпретации, роли)
   - Сборка форм: создание целого с сохранением различий
   - Системное мышление: видение системы целиком

3. **Научная база:**
   - Complexity Leadership Theory (Uhl-Bien)
   - Self-Determination Theory (Deci & Ryan)
   - Polyvagal Theory (Porges)
   - Paradoxical Leadership
   - Vertical Development (Kegan, Torbert)
   - Systems Psychodynamics (Bion, Winnicott)

4. **Уровни развития:**
   - Реактивность/Новичок: локальные решения, контроль
   - Интеграция/Практик: сцепки, системное мышление
   - Архитектура/Зрелость: среда, передача субъектности

### Формат вывода

- Используй формат **Markdown**
- Структурируй заголовками `##`, `###`
- Используй списки для перечисления
- Пиши простым, понятным языком
- Будь конкретным, избегай абстракций
- Используй примеры из реальной жизни

## Как использовать скрипт

### 1. Настройка API ключа

Создайте файл `.env` в корне проекта или установите переменную окружения:

```bash
OPENAI_API_KEY=your_api_key_here
```

Или в PowerShell:
```powershell
$env:OPENAI_API_KEY="your_api_key_here"
```

### 2. Запуск скрипта

```bash
cd leadership-architect
python scripts/enhance-quest-theories.py
```

Скрипт:
- Загружает все квесты из `data/quest-templates.json`
- Проверяет, есть ли у каждого квеста достаточно подробная теория
- Для квестов без теории или с недостаточной теорией генерирует новую с помощью ИИ
- Сохраняет результат в `data/quest-templates-enhanced.json`

### 3. Проверка результата

Проверьте файл `quest-templates-enhanced.json`:
- Убедитесь, что теории дополнены правильно
- Проверьте, что нет дублирования с шагами и критериями
- Убедитесь, что теории содержат все необходимые элементы

### 4. Применение результата

После проверки замените оригинальный файл:

```bash
# Windows PowerShell
Copy-Item data/quest-templates-enhanced.json data/quest-templates.json -Force

# Linux/Mac
cp data/quest-templates-enhanced.json data/quest-templates.json
```
