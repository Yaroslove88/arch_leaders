## Структура работ: 5 PR’ов (самый короткий путь к 8/10)

### PR1 — Контракты JSON + runtime-валидация (самая быстрая стабилизация)

**Цель:** убрать `as any` вокруг Prisma Json и начать ловить поломки данных сразу.

**Что делаем**

1. В `apps/api/src/common/` добавить:
    

- `schemas/` (zod)
    
- `types/` (тип-экспорты)
    
- `mappers/` (Prisma → Domain/DTO)
    

2. Описать Zod-схемы для первых критичных JSON:
    

- `Session.insights_json`
    
- `Session.focus_json`
    
- `Session.ability_signals_json`
    
- `Quest.steps_json`
    
- `Quest.criteria_json`
    
- `Quest.reward_json`
    

3. Все места `as any[] / as any` заменить на:
    

- `Schema.parse(...)` на чтении из БД
    
- `Schema.parse(...)` или `Schema.safeParse(...)` на записи (на границе use-case)
    

**Минимальный каркас**

- `apps/api/src/common/schemas/session.schema.ts`
    
- `apps/api/src/common/schemas/quest.schema.ts`
    

**Definition of done**

- Ноль `as any` в этих JSON путях
    
- Ошибки схем логируются с `requestId`

### PR2 — Orchestration: убрать цикл Sync ↔ Quests без очередей

**Цель:** удалить `forwardRef` и сделать зависимость односторонней.

**Идея**

- `Sync` больше не знает про `QuestGenerationService`.
    
- Он завершает анализ и вызывает `QuestOrchestrationService`.
    

**Реализация**

1. Новый модуль:
    

- `apps/api/src/orchestration/orchestration.module.ts`
    
- `QuestOrchestrationService`
    

2. В `QuestOrchestrationService`:
    

- `handleSessionAnalyzed(sessionId: string)`:
    
    - берёт session через repo/service
        
    - зовёт генератор квестов (чистая генерация)
        
    - сохраняет квесты через repo
        

3. `SyncService` после анализа:
    

- вызывает orchestration, но **без импорта QuestsModule** (только OrchestrationModule)
    

**Definition of done**

- `forwardRef` между Sync/Quests исчез
    
- Генерация квестов работает как раньше

### PR3 — Repository слой + разрез QuestsService (убрать цикл QuestsService ↔ QuestGenerationService)

**Цель:** генератор квестов не должен сохранять, сервис не должен зависеть на генератор циклом.

**Что делаем**

1. `QuestRepository` (инфра):
    

- `findById`
    
- `createMany`
    
- `updateStatus`
    
- `listForUser`  
    (внутри Prisma)
    

2. `QuestGenerationService` превращаем в “чистый”:
    

- вход: `SessionAnalysisResult` / типизированный контекст
    
- выход: `GeneratedQuest[]` (DTO/Domain)
    

3. Сохранение — только в use-case/orchestration (`QuestOrchestrationService`)
    

**Definition of done**

- нет `@Inject(forwardRef(() => QuestsService))` в генераторе
    
- `QuestsService` становится тоньше (CRUD + правила)

### PR4 — TypeScript strict: включаем `strictNullChecks` правильно

**Цель:** поднять типобезопасность без массового “починить всё сразу”.

**Тактика**

- Включаем `strictNullChecks: true` в `apps/api/tsconfig.json`
    
- `noImplicitAny` пока НЕ трогаем
    
- Чиним только реальные ошибки компилятора, не “переписываем всё”
    

**Пара правил**

- На границах (контроллеры, Prisma, LLM) — `unknown` + zod
    
- Внутри домена — строгие типы
    

**Definition of done**

- `pnpm -C apps/api typecheck` проходит
    
- Сборка проходит
    

---

### PR5 — LLM subsystem: retry + structured logs + zod на ответы

**Цель:** LLM перестаёт быть “рандомным генератором багов”.

**Что делаем**

1. В `LLMService`:
    

- retry 2 раза + backoff
    
- лог latency + модель + токены + requestId
    
- сохранять raw response при ошибке парсинга
    

2. Парсинг:
    

- всё, что приходит от LLM как JSON, прогоняем через zod
    
- при fail: сохраняем raw + причину
    

**Definition of done**

- при кривом ответе LLM система не падает, а создаёт “ошибочный run” и корректный статус

## Workspace: чтобы всё это не развалило сборку

### 1) Единые команды в корне

В root `package.json` (примерно):

```json
{
  "scripts": {
    "dev:web": "pnpm -C apps/web dev",
    "dev:api": "pnpm -C apps/api dev",
    "typecheck": "pnpm -r typecheck",
    "lint": "pnpm -r lint"
  }
}
```

В `apps/api/package.json`:

```json
{
  "scripts": {
    "typecheck": "tsc --noEmit -p tsconfig.json"
  }
}
```

### 2) Версии React / Nest / Prisma — выровнять через overrides (если нужно)

В root:

```json
{
  "pnpm": {
    "overrides": {
      "react": "18.3.1",
      "react-dom": "18.3.1"
    }
  }
}
```

(версию поставь ту, что у тебя фактически используется — смысл в консистентности)

## Минимальные архитектурные правила (чтобы рефакторинг не откатился назад)

1. **Контроллеры не возвращают Prisma модели**
    
2. Prisma JSON читаем/пишем только через `zod`
    
3. Генераторы (LLM / QuestGeneration) **не пишут в БД**
    
4. Сохранение в БД — только в use-case/orchestration/repo
    
5. `forwardRef` — временно допустим только в одном месте и с тикетом на удаление
