## Философия дизайна

**Базовая формула:** McKinsey-level intellect × psychological depth × modern leadership × architectural thinking

**Принципы интерфейса:**
1. **Визуальная иерархия** — важное крупнее, второстепенное компактнее
2. **Прогресс виден** — всегда понятно, где ты и куда движешься
3. **Контекстная помощь** — подсказки появляются там, где нужны
4. **Минимализм с глубиной** — простота на поверхности, детали по запросу
5. **Архитектурное мышление** — интерфейс как стратегическая система, не набор элементов
6. **Интеллектуальная зрелость** — элитарный консалтинговый уровень, не игровой интерфейс

**Использование смайликов в этом документе:**
- Смайлики в ASCII-артах используются для **семантической маркировки** секций (📝, ⚡, 📊, ⚠️, 🌳)
- Это соответствует правилам из [IMAGE_GENERATION_PROMPTS.md](./docs/design-system/IMAGE_GENERATION_PROMPTS.md): смайлики уместны для категоризации контента и заголовков секций
- В реальном интерфейсе смайлики используются ограниченно (см. секцию про смайлики в IMAGE_GENERATION_PROMPTS.md)

## 1. АРХИТЕКТУРА: Отображение веток и узлов

### 1.1. Визуализация веток (Branch Cards)

**Концепция:** Ветка — это не просто список узлов, а живая система с прогрессом и направлением.

```
│  🌳 КАРТА СПОСОБНОСТЕЙ                               │

│  │  Основа архитектурного лидерства.           │    │

│                                                     │
│  ┌────────────────────────────────────────────┐    │
│  │ 🏗️ АРХИТЕКТУРНОЕ МЫШЛЕНИЕ                  │    │
│  │ ────────────────────────────────────────   │    │
│  │                                             │    │
│  │  ██████░░░░░░░░░░░░░░  30%                  │    │

└─────────────────────────────────────────────────────┘
```

**Ключевые элементы карточки ветки:**

1. **Заголовок** — название ветки + иконка
2. **Краткое описание** — объяснение ветки в контексте архитектурного лидерства (2-3 предложения)
3. **Прогресс-бар** — визуальный индикатор развития
4. **Статистика** — "X из Y узлов активны"
5. **Контекстная подсказка** — текущий фокус / рекомендация / статус

> 💡 **Клик на карточку** раскрывает ветку и показывает узлы (без отдельной кнопки)

**Состояния карточки ветки:**

- **Активная** — яркая граница, тень, hover-эффект
- **Рекомендуемая** — пульсирующая граница, иконка ⚡
- **С перекосом** — предупреждающий цвет, иконка ⚠️
- **Растущая** — зелёный акцент, иконка 📈

### 2.2. Карточка квеста (Quest Card) — Список

**Концепция:** Компактная карточка для списка квестов. Шаги не показываются, так как их может быть много (до 10+).

```
┌─────────────────────────────────────────────────────┐
│  ⚔️ КВЕСТ: Удержание напряжения                    │
│  ─────────────────────────────────────────────     │
│                                                     │
│  📅 Недельный │ 🏷️ Субъектность │ Награда: 50 XP  │
│                                                     │
│  📝 "Если я научусь удерживать напряжение в        │
│      разговоре, не бросаясь решать проблему,       │
│      команда начнёт находить решения сама"         │
│                                                     │
│  📈 Прогресс: ████████░░ 65%                       │
│  2 из 4 шагов выполнено                            │
│                                                     │
│  🌳 Развивает: [Субъектность +15%] [Удержание +10%]│
│                                                     │
│  [Открыть квест →]                                 │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**Варианты состояния:**

- **Активен** — синяя граница, прогресс виден, кнопка "Продолжить"
- **Отложен** — серая граница, кнопка "Активировать"
- **Завершён** — зелёная граница, галочка ✅, кнопка "Повторить"

**Особенности:**

- **Без списка шагов** — шаги не показываются в списке (их может быть много)
- **Прогресс-бар** — визуальный индикатор выполнения (X из Y шагов)
- **Краткая гипотеза** — главная идея квеста, отображается в выделенном блоке с иконкой 📝
- **Развивает** — показывает процент прогресса узлов (см. раздел 12), отображается как массив узлов с процентами
- **Типы квестов на русском** — "Микро-квест" (micro), "Недельный" (weekly), "Сюжетный" (story)

**Ключевые элементы:**

1. **Заголовок** — название, теги, тип (на русском: Микро-квест/Недельный/Сюжетный), награда
2. **Гипотеза** — главная идея квеста, отображается в выделенном блоке с фоном и рамкой
3. **Интерактивный прогресс** — кликабельные шаги для отметки выполнения с индикатором "← ТЫ ЗДЕСЬ" для активного шага
4. **Критерии успеха** — чек-лист выполнения с интерактивными чекбоксами
5. **Влияние на дерево** — XP награда и массив узлов с процентами
6. **Доказательства** — кнопка для добавления доказательств, выделена цветом (system-focus) для привлечения внимания
7. **CTA** — кнопка завершения квеста

**Механика кликабельных шагов:**

- При клике на шаг открывается мини-модальное окно: "Отметить шаг как выполненный?"
- Опционально можно добавить краткую запись о выполнении
- Шаги можно отмечать в любом порядке
- Прогресс обновляется автоматически

**Блок доказательств:**

- Отображается как кнопка, выделенная цветом (system-focus) для привлечения внимания
- Стиль: `bg-system-focus/10 border-2 border-system-focus/30`
- Текст: "Зафиксируй следы практики" или "У тебя X доказательств"
- При клике открывает модальное окно добавления доказательства (см. раздел 4.2)
- После завершения квеста показывается список существующих доказательств (если есть)

### 2.4. Карточка кейса (Case Card) — Список

**Концепция:** Компактная карточка для списка кейсов. Кейс — это одноразовый выбор варианта, без прогресса выполнения.

```

│                                                     │
│  ✅ Пройден │ Выбран вариант B                      │
│                                                     │
│  🌳 Развивает: [Удержание +5%] [Системное +3%]     │
│                                                     │
│  [Открыть кейс →]                                  │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**Варианты состояния:**

- **Не начат** — серая граница, кнопка "Начать кейс"
- **Пройден** — зелёная граница, галочка ✅, показан выбранный вариант, кнопка "Повторить"

**Особенности:**

- **Крючок** — драматичное начало кейса, привлекающее внимание
- **Теги способностей** — категории способностей, которые развивает кейс
- **Развивает** — показывает влияние на дерево (массив узлов с процентами)
- **Без прогресса** — кейс это одноразовый выбор варианта, прогресс есть только в квестах

**Блок рефлексии:**

- Отображается как кнопка после выбора варианта, выделенная цветом (system-focus) для привлечения внимания
- Стиль: `bg-system-focus/10 border-2 border-system-focus/30`
- Текст: "Рефлексия (опционально)" с подсказкой "Зафиксируй свои мысли и инсайты"
- При клике открывает модальное окно рефлексии (см. раздел 4.3)
- Рефлексия опциональна и не блокирует завершение кейса

## 12. СИСТЕМА ОПЫТА И ПРОГРЕССА

### 12.1. Как работает опыт (XP)

**Источники опыта:**

1. **Квесты:**
   - Базовый XP: указывается в награде квеста (например, 50 XP)
   - Начисляется при завершении квеста
   - Пример: "Награда: 50 XP"

2. **Кейсы:**
   - Базовый XP зависит от сложности:
     - Базовый (basic): 50 XP
     - Средний (intermediate): 100 XP
     - Сложный (advanced): 150 XP
   - Начисляется при первом прохождении кейса (выборе варианта)
   - Повторное прохождение не даёт XP

3. **Доказательства (следы):**
   - Могут давать дополнительный XP, если указано в квесте
   - Обычно не дают XP напрямую, а влияют на прогресс квеста

### 12.2. Что означает "Развивает: Субъектность +15%"

**Важно:** "+15%" — это не XP, а процент прогресса узла.

**Как это работает:**

1. **Квест завершён** → начисляется базовый XP (например, 50 XP)
2. **XP распределяется по связанным узлам:**
   - Если в квесте указано `skill_xp: 50`, то этот опыт распределяется между `linked_nodes`
   - Например, если квест связан с узлами "Субъектность" и "Удержание напряжения", то 50 XP делится между ними
3. **Процент прогресса:**
   - Каждый узел имеет `xp_required` (например, 400 XP для уровня)
   - Полученный XP добавляется к `xp_current` узла
   - Процент = `(xp_current / xp_required) * 100`
   - "+15%" означает, что прогресс узла увеличится на 15% от требуемого опыта

**Пример расчёта:**

```
Узел "Субъектность":
- Требуется: 400 XP для следующего уровня
- Текущий XP: 200 XP (50%)
- Квест даёт: 50 XP к узлу
- Новый прогресс: 250 XP (62.5%)
- Увеличение: +12.5% (не +15%, так как 50 XP от 400 = 12.5%)
```

**Отображение в интерфейсе:**

- "Развивает: [Субъектность +15%]" означает примерное увеличение прогресса
- Реальное увеличение зависит от `xp_required` узла
- Если узел уже на 90%, то +15% может быть невозможно (максимум 100%)

### 12.3. Прогресс узлов

**Уровни узлов:**

- Каждый узел имеет уровень (1-10 или больше)
- Для перехода на следующий уровень требуется определённое количество XP (`xp_required`)
- Прогресс отображается как процент: `(xp_current / xp_required) * 100`

**Состояния узлов:**

- **Заблокирован** — не хватает XP или не выполнены prerequisites
- **Доступен** — можно начать развивать
- **Активен** — в процессе развития (есть активные квесты/кейсы)
- **Разблокирован** — достигнут минимальный уровень
- **Интегрирован** — достигнут высокий уровень интеграции

### 12.4. Формулы расчёта

**XP за квест:**
```
XP_quest = reward.xp (базовый XP из награды квеста)
```

**XP за кейс:**
```
XP_case = {
  'basic': 50,
  'intermediate': 100,
  'advanced': 150
}[difficulty]
```

**Прогресс узла:**
```
progress_percent = (xp_current / xp_required) * 100
```

**Распределение skill_xp по узлам:**
```
Если квест имеет skill_xp: 50 и linked_nodes: [node1, node2]
То каждый узел получает: skill_xp / количество_узлов = 50 / 2 = 25 XP
```

**Увеличение прогресса:**
```
delta_percent = (skill_xp / xp_required) * 100
```

### 12.5. Отображение в карточках

**В карточке квеста:**
- "Награда: 50 XP" — базовый XP за завершение
- "Развивает: [Субъектность +15%]" — примерное увеличение прогресса узла
- Реальное увеличение зависит от `xp_required` узла

**В карточке кейса:**
- После прохождения показывать: "Получено: 50 XP" (или 100/150 в зависимости от сложности)
- Показывается "Развивает: [Узел +X%]" — процент увеличения прогресса узла

**В карточке узла:**
- Показывается текущий прогресс: "Уровень 4 │ ████████░░ 80%"
- Показывается XP: "XP: 320 / 400"

### 12.6. Документация для пользователя

**Где показывать информацию:**

1. **В детальной карточке квеста:**
   - Раздел "Награды" с объяснением:
     - "Завершение квеста даёт 50 XP"
     - "Это увеличит прогресс узла 'Субъектность' примерно на 15%"

2. **В детальной карточке кейса:**
   - После выбора варианта показывать:
     - "Получено: 50 XP" (или 100/150 в зависимости от сложности)
     - "Прогресс узла 'Удержание' увеличился на X%" (рассчитывается автоматически)

3. **В карточке узла:**
   - Показывать текущий XP и требуемый для следующего уровня
   - Показывать, сколько XP нужно для следующего уровня
