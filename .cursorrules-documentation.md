# Правила автоматической классификации и размещения документов

> **Дата создания:** 15.01.2025  
> **Статус:** Активные правила

Эти правила определяют, куда автоматически помещать новые документы на основе их названия и содержимого.

---

## 🎯 Общий принцип

**ВСЕ новые документы (`.md` файлы) должны автоматически размещаться в соответствующих папках `docs/` на основе их темы.**

Если тема не определена или не совпадает с существующими категориями, документ помещается в `docs/` (корень документации).

## 🔍 Алгоритм определения папки

### Шаг 1: Анализ названия файла

1. Преобразовать название в UPPERCASE
2. Проверить наличие ключевых слов в порядке приоритета (сверху вниз)
3. Если найдено совпадение → использовать соответствующую папку

### Шаг 2: Анализ содержимого (если название не определило папку)

Если по названию не удалось определить папку, проанализировать первые 200 символов содержимого:

1. Искать ключевые слова из маппинга в содержимом
2. Проверять заголовки (H1, H2) на наличие ключевых слов
3. Если найдено совпадение → использовать соответствующую папку

### Шаг 3: Размещение по умолчанию

Если тема не определена:
- **Разместить в `docs/`** (корень документации)
- **НЕ размещать в корне проекта** (кроме контентных данных)

## 📝 Правила именования файлов

### Формат имени файла

```
<TЕМА>_<ПОДТЕМА>_<СТАТУС>.md
```

**Где:**
- `<ТЕМА>` — основная тема (QUEST, CASE, ABILITY, DESIGN, AUTH, ADMIN, AUDIT, SETUP, API, ERROR, CONTENT, USER_FLOW)
- `<ПОДТЕМА>` — уточнение (SYSTEM, UX, UI, MIGRATION, FIX, GUIDE)
- `<СТАТУС>` — статус документа (COMPLETE, SPECIFICATION, REPORT, CHECKLIST)

### Примеры правильных названий

✅ **Правильно:**
- `QUEST_SYSTEM_COMPLETE.md`
- `CASES_UX_UI_SPECIFICATION.md`
- `ABILITY_STATE_ARCHITECTURE_ANALYSIS.md`
- `DESIGN_SYSTEM_V01.md`
- `AUTHENTICATION.md`
- `ADMIN_PANEL_IMPLEMENTATION.md`
- `AUDIT_REPORT_2025.md`
- `SETUP.md`
- `API_DOCUMENTATION.md`
- `ERROR_HANDLING_GUIDE.md`
- `CONTENT_USAGE_GUIDE.md`
- `USER_FLOW_DETAILED.md`

❌ **Неправильно:**
- `quest-system.md` (не UPPERCASE, нет подчеркиваний)
- `New Document.md` (не описательное)
- `doc1.md` (не информативное)
- `00_quest.md` (префикс не нужен)

## 🚫 Исключения

### Файлы, которые НЕ перемещаются в `docs/`

1. **Контентные данные** (остаются в корне):
   - `QUESTS_STRUCTURED_CONTENT.md`
   - `QUESTS_THEORIES_MAPPING.md`
   - Любые файлы с данными, а не документацией

2. **Специальные файлы проекта**:
   - `README.md` (в корне проекта)
   - `ОПИСАНИЕ_БИЗНЕСА.md` (бизнес-документация)
   - Файлы в `scripts/`, `apps/`, `packages/`

3. **Файлы с префиксом `00_`**:
   - Считаются временными/черновиками
   - Могут быть перемещены в `docs/archive/misc/` при систематизации

## ✅ Чеклист при создании документа

Перед созданием нового документа:

- [ ] Определить тему по ключевым словам
- [ ] Выбрать правильное название файла (UPPERCASE, подчеркивания)
- [ ] Убедиться, что название содержит ключевые слова из маппинга
- [ ] Создать файл в правильной папке `docs/<тема>/`
- [ ] Если тема не определена → создать в `docs/`
- [ ] Обновить `README.md` соответствующей папки (если нужно)

## 🔄 Автоматизация

### Для AI ассистентов (Cursor, GitHub Copilot, и т.д.)

При создании нового `.md` файла:

1. **Проанализировать название файла** на наличие ключевых слов
2. **Если ключевые слова найдены** → создать файл в соответствующей папке `docs/<тема>/`
3. **Если ключевые слова не найдены** → создать файл в `docs/`
4. **Предложить пользователю** переместить файл, если он был создан не в той папке

### Примеры команд для AI

```
"Создай документ QUEST_SYSTEM_SPECIFICATION.md"
→ Создать в docs/quests/QUEST_SYSTEM_SPECIFICATION.md

"Создай документ про настройку базы данных"
→ Создать в docs/setup/DATABASE_SETUP.md (или DATABASE_CONFIGURATION.md)

"Создай документ про новую фичу"
→ Создать в docs/ (если тема не определена)
```
