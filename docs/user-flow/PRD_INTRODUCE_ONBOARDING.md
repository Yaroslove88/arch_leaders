## 🎯 Обзор

### Назначение страницы

**Introduce** — это страница онбординга, которая:
- Приветствует пользователя в системе
- Объясняет, как устроена RPG-система обучения
- Показывает, как пользоваться инструментами (квесты, кейсы, записи, дерево способностей)
- Объясняет интерфейс и навигацию
- Помогает начать работу с первого шага

### Ключевой принцип

> **Не продажа, а инструкция по использованию**

Страница — это **практический гайд** по системе, который помогает понять:
- Что означают элементы RPG
- Как читать интерфейс
- Как начать работать
- Куда идти дальше

## 👥 Целевая аудитория

### Первичная аудитория

**Руководители и лидеры, которые:**
- Чувствуют ограничения традиционных моделей управления
- Работают в условиях неопределённости
- Хотят развивать не навыки, а способ мышления
- Готовы к глубокой рефлексии и практике
- Ищут системный подход, а не набор техник

### Характеристики пользователя

- **Опыт:** От среднего до продвинутого уровня руководства
- **Мотивация:** Внутренняя, не внешняя (не "для галочки")
- **Готовность:** К рефлексии, к работе с собой
- **Ожидания:** Не "быстрый результат", а глубокое понимание

## 📚 Контекст курса

### Ядро курса "Архитектурное лидерство"

> Лидер — это не тот, кто знает ответы.  
> Это тот, кто умеет **создать среду**, в которой возникают:
> - различия (а не однобокость),
> - сцепки (а не контроль),
> - субъектность (а не исполнение),
> - зрелость (а не реактивность),
> - движение (а не выживание).

### Ключевые предпосылки курса

1. **Мир больше не работает по плану** — нужна навигация в неопределённости
2. **Иерархия не гарантирует влияние** — важна личная зрелость
3. **Ответственность — это связь, а не задача**
4. **Субъектность — ключевая способность лидера**
5. **Организация — это поле взаимодействий, а не структура**
6. **Архитектурное мышление можно развить** — это навык, не дар

### Структура системы обучения

**6 веток способностей:**
1. 🧠 **Субъектность** — внутренняя устойчивость, действие из себя
2. 🧱 **Архитектурное мышление** — мышление формами, создание сцепок
3. ⚖️ **Ответственность** — ответственность как связь, а не груз
4. 🌱 **Среда зрелости** — создание условий для роста команды
5. ⚡ **Устойчивость** — способность меняться, не теряя целостности
6. 🔄 **[Дополнительная ветка]** — [уточнить из дерева способностей]

**Форматы работы:**
- 📝 **Записи** — ситуации, рефлексия, обратная связь
- 🎮 **Квесты** — эксперименты в реальности (Micro, Weekly, Story, In-person)
- 📊 **Кейсы** — интерактивные управленческие ситуации
- 🌳 **Дерево способностей** — визуализация прогресса
- 📈 **Сессии** — анализ ситуаций с помощью AI
- 💎 **Доказательства** — фиксация практики

## 📐 Структура страницы

### Общая структура

Страница состоит из **последовательных блоков-инструкций**, которые объясняют, как пользоваться системой.

```
[ Hero Section / Приветствие ]
  ↓
[ Что такое Life-RPG система ]
  ↓
[ Цикл работы в системе ]
  ↓
[ Инструменты системы (подробно) ]
  - Записи
  - Квесты
  - Кейсы
  - Дерево способностей
  - Сессии
  - Доказательства
  ↓
[ Интерфейс и навигация ]
  ↓
[ Первый шаг ]
```

### Принцип построения

**От общего к частному, от понимания к действию**

- **Общее:** Что такое система и как она работает
- **Частное:** Как пользоваться каждым инструментом
- **Практика:** Первый шаг для начала работы

### 5. Блок "Как это работает" / "Формат обучения"

**Назначение:** Объяснить цикл работы в системе

**Структура:**
- **Заголовок:** "Как это работает"
- **Цикл:** Ситуация → Анализ → Квесты → Практика → Доказательства → Прогресс
- **Описание каждого этапа** (кратко)
- **Визуал:** Схема цикла (диаграмма или timeline)

**Контент:**

**Заголовок:**
"Как это работает"

**Цикл развития:**

```
Ситуация → Анализ → Квесты → Практика → Доказательства → Прогресс
```

**Этапы:**

1. **Ситуация**
   - Описываете ситуацию из жизни, где проявили лидерство или столкнулись с вызовом
   - Это может быть встреча, решение, обратная связь

2. **Анализ**
   - AI анализирует вашу ситуацию
   - Выявляет паттерны, темы, сигналы способностей
   - Определяет области для развития

3. **Квесты**
   - Система предлагает квесты для практики
   - Micro (1-3 дня), Weekly (неделя), Story (2-4 недели), In-person (события)

4. **Практика**
   - Выполняете квесты в реальности
   - Экспериментируете с новыми подходами
   - Применяете способности в рабочих ситуациях

5. **Доказательства**
   - Фиксируете результаты практики
   - Добавляете доказательства применения способностей
   - Создаёте новые записи о развитии

6. **Прогресс**
   - Отслеживаете прогресс по дереву способностей
   - Разблокируете новые узлы
   - Видите, как развивается ваше лидерство

**Визуальный стиль:**
- Схема цикла (диаграмма или горизонтальный timeline)
- Краткие описания под каждым этапом
- Возможно: анимированный переход между этапами (опционально)

**Рабочие цвета:**
- Structural Cyan — `#3A6F8F` (связи, аналитика)
- Muted Teal — `#2F8C8C` (устойчивость, процессы)

- Tension Amber — `#F2A03D` (конфликт, внимание)

**Для страницы Introduce:**
- Основной фон: Deep Graphite
- Панели/блоки: Cold Concrete (с лёгкой прозрачностью)
- Акценты: Structural Cyan (для CTA), Emergence Green (для позитивных элементов)
- Текст: Steel Gray (основной), белый (заголовки)

### Типографика

**Шрифты:**
- Inter / SF Pro / Manrope (инженерно-нейтральные)
- Короткие, точные тексты
- Без маркетинговых эпитетов

**Размеры:**
- Заголовки H1: `text-4xl` или `text-5xl` (Hero)
- Заголовки H2: `text-3xl` (блоки)
- Заголовки H3: `text-2xl` (подразделы)
- Основной текст: `text-base` или `text-lg`
- Вторичный текст: `text-sm`

### Компоненты

**Карточки/Панели:**
- Не "плитки", а **панели**
- Лёгкая прозрачность (`bg-opacity-80`)
- Тонкая рамка (`border border-ui-border-soft`)
- Мягкая тень
- Градиент фона (`bg-panel-gradient`) — опционально
- Левая цветная граница (`border-l-4`) — для акцента

**Кнопки:**
- Основная CTA: Structural Cyan или Emergence Green
- Вторичная: прозрачная, с рамкой
- Размер: достаточно крупный для кликабельности

**Списки:**
- Структурированные отступы
- Маркеры минималистичные (точки или тире)
- Достаточный межстрочный интервал

## 👤 Пользовательские сценарии

### Сценарий 1: Полный онбординг (оптимистичный путь)

1. Пользователь попадает на страницу `/introduce`
2. Читает Hero Section → понимает, что это приветствие и инструкция
3. Читает "Что такое Life-RPG система" → понимает формат
4. Изучает "Цикл работы" → понимает, как работает система
5. Просматривает "Инструменты системы" → изучает каждый инструмент:
   - Записи — как создавать
   - Квесты — типы и статусы
   - Кейсы — как проходить
   - Дерево способностей — как читать
   - Сессии — что это такое
   - Доказательства — как фиксировать
6. Изучает "Интерфейс и навигацию" → понимает, где что находится
7. Читает "Первый шаг" → понимает, что делать дальше
8. Нажимает "Создать первую запись" → переходит на `/entries/new`

**Результат:** Пользователь понимает, как пользоваться системой, и готов начать работу.

---

### Сценарий 2: Быстрое изучение (пользователь торопится)

1. Пользователь попадает на страницу `/introduce`
2. Читает Hero Section → понимает, что это инструкция
3. Прокручивает до "Цикл работы" → быстро изучает основную схему
4. Просматривает "Инструменты системы" → бегло просматривает ключевые моменты
5. Читает "Первый шаг" → понимает, что делать
6. Нажимает "Создать первую запись" → переходит на `/entries/new`

**Результат:** Пользователь получил базовое понимание системы и готов начать.

---

### Сценарий 3: Глубокое изучение (пользователь хочет понять всё)

1. Пользователь попадает на страницу `/introduce`
2. Внимательно читает все блоки по порядку
3. Изучает каждый инструмент подробно, возвращается к непонятным местам
4. Открывает интерактивные элементы (если есть мини-кейс или дерево) → пробует
5. Возвращается к блокам, перечитывает инструкции
6. Нажимает "Создать первую запись" → переходит на `/entries/new`

**Результат:** Пользователь глубоко понимает систему и уверен, как ей пользоваться.

## 🔧 Технические требования

### Роутинг

**URL:** `/introduce`

**Маршрут:**
```typescript
// apps/web/src/app/introduce/page.tsx
```

### Компоненты

1. **`IntroducePage`** — основной компонент страницы
2. **`HeroSection`** — Hero блок / Приветствие
3. **`LifeRPGExplanationBlock`** — блок "Что такое Life-RPG система"
4. **`CycleBlock`** — блок "Цикл работы в системе"
5. **`ToolsBlock`** — блок "Инструменты системы"
   - `EntryToolSection` — секция про записи
   - `QuestToolSection` — секция про квесты
   - `CaseToolSection` — секция про кейсы
   - `TreeToolSection` — секция про дерево способностей
   - `SessionToolSection` — секция про сессии
   - `EvidenceToolSection` — секция про доказательства
6. **`InterfaceNavigationBlock`** — блок "Интерфейс и навигация"
7. **`FirstStepBlock`** — блок "Первый шаг"
8. **`InteractivePreview`** — интерактивный превью (опционально, мини-кейс или дерево)
9. **`TreePreview`** — упрощённый превью дерева способностей (опционально)
10. **`MiniCasePreview`** — мини-кейс для превью (опционально)

### Данные

**Статические данные:**
- Тексты блоков (можно вынести в константы или markdown)
- Описания инструментов системы
- Описания типов квестов, статусов, уровней
- Мини-кейс (упрощённая версия существующего кейса, опционально)

**Динамические данные (опционально):**
- Если используется реальное дерево способностей → загрузка через API (упрощённая версия)
- Если используется реальный кейс → загрузка через API (упрощённая версия)

### Производительность

- Страница должна загружаться быстро (< 2 секунд)
- Интерактивные элементы (дерево, кейс) должны работать плавно
- Ленивая загрузка для тяжёлых компонентов (если нужно)

### Адаптивность

- **Desktop:** Полная версия, все блоки видны
- **Tablet:** Адаптация размера блоков, возможно вертикальная прокрутка для дерева
- **Mobile:** Вертикальная прокрутка, компактные блоки, упрощённое дерево (если используется)

## 📊 Метрики успеха

### Основные метрики

1. **Конверсия в первое действие**
   - % пользователей, которые перешли на `/entries/new` (или `/login`/`/register`)
   - Цель: > 30% (если есть регистрация) или > 50% (если регистрация не требуется)

2. **Время на странице**
   - Среднее время на странице
   - Цель: 3-5 минут (время на изучение инструкций)

3. **Интерактивность**
   - % пользователей, которые попробовали мини-кейс (или интерактивный элемент)
   - Цель: > 60%

4. **Прокрутка страницы**
   - % пользователей, которые прокрутили до конца страницы
   - Цель: > 70%

### Дополнительные метрики

5. **Возвраты**
   - % пользователей, которые вернулись на страницу после первого визита (для повторного изучения)
   - Цель: 10-15% (естественное поведение при изучении новой системы)

### События для аналитики

- `introduce_page_view` — просмотр страницы
- `introduce_resonance_scroll` — прокрутка до блока "Резонанс"
- `introduce_tree_interaction` — взаимодействие с деревом
- `introduce_case_start` — начало мини-кейса
- `introduce_case_complete` — завершение мини-кейса
- `introduce_cta_click` — клик на CTA "Создать первую запись"

## 📝 Примечания

### Важные принципы

1. **Не продавать, а резонировать** — страница должна создавать ощущение "это про меня", а не "это надо купить"

2. **Честность** — не обещать быстрый результат, честно показывать формат работы (практика, рефлексия, время)

3. **Минимализм** — не перегружать информацией, оставить пространство для размышления

4. **Действие** — цель — перевести пользователя к первому действию, а не просто информировать

### Открытые вопросы

1. **Требуется ли регистрация перед началом?**
   - Если да → CTA ведёт на `/login` или `/register`
   - Если нет → CTA ведёт на `/entries/new`

2. **Нужны ли интерактивные элементы (мини-кейс, дерево)?**
   - Рекомендация: можно убрать, оставить только инструкции
   - Если оставлять: мини-кейс дает тактильное ощущение, но не обязателен для онбординга

3. **Нужен ли блок "Превью дерева способностей" в разделе инструментов?**
   - Можно добавить интерактивное превью
   - Или оставить только описание и ссылку на `/tree`

4. **Нужна ли кнопка "Посмотреть дерево способностей" в блоке "Первый шаг"?**
   - Может быть полезно для пользователей, которые хотят сначала изучить дерево
   - Опционально
