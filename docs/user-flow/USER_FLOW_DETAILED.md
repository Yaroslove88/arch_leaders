# Детальный User Flow для игры "Архитектор лидерства"

## 🎯 Общая концепция

Игра построена на цикле: **Ситуация → Анализ → Квесты → Практика → Доказательства → Прогресс**

---

## 📱 Детальные сценарии взаимодействия

### Сценарий 1: Первый запуск и онбординг

#### Шаг 1: Главная страница (`/`)
**Что видит пользователь:**
- Заголовок: "Архитектор лидерства"
- Подзаголовок: "Life-RPG система для развития лидерских способностей"
- Краткое описание: "Развивайте лидерские способности через практику и рефлексию"
- Preview дерева способностей (6 веток)
- Кнопка "Начать путь"

**Действия пользователя:**
- Читает описание
- Просматривает дерево способностей
- Нажимает "Начать путь"

**Что происходит:**
- Переход на `/entries/new` (создание первой записи)

---

#### Шаг 2: Создание первой записи (`/entries/new`)
**Что видит пользователь:**
- Форма с полями:
  - Тип записи (dropdown): ситуация, рефлексия, обратная связь, голосовое сообщение
  - Текст (textarea, большая)
  - Участники (tags input)
  - Теги (tags input)
  - Контекст (JSON editor, опционально)
- Подсказки:
  - "Опишите ситуацию, где вы проявили лидерство или столкнулись с вызовом"
  - Примеры ситуаций (кликабельные):
    - "Провел сложную встречу с командой"
    - "Принял решение в условиях неопределенности"
    - "Получил обратную связь от коллеги"
- Кнопки:
  - "Сохранить как черновик"
  - "Сохранить и проанализировать"

**Действия пользователя:**
- Заполняет форму
- Выбирает пример или пишет свою ситуацию
- Нажимает "Сохранить и проанализировать"

**Что происходит:**
- Запись сохраняется в БД
- Создается Session со статусом "analyzing"
- Пользователь перенаправляется на `/sessions/[id]` с показом процесса анализа

---

#### Шаг 3: Анализ сессии (`/sessions/[id]`)
**Что видит пользователь:**

**Во время анализа:**
- Индикатор загрузки: "Анализируем вашу ситуацию..."
- Прогресс-бар (если возможно)
- Сообщение: "Это может занять 30-60 секунд"

**После анализа:**
- **Секция: Резюме**
  - Краткое резюме ситуации (1-2 абзаца)
  
- **Секция: Инсайты**
  - Список инсайтов (3-5 пунктов)
  - Каждый инсайт с иконкой и описанием
  
- **Секция: Паттерны**
  - Выявленные поведенческие паттерны
  - Теги паттернов
  
- **Секция: Темы**
  - Основные темы ситуации
  - Теги тем
  
- **Секция: Сигналы способностей**
  - Список способностей, которые проявились или нужны
  - Каждая способность:
    - Название
    - Связь с узлом дерева
    - Уровень сигнала (сильный/средний/слабый)
    - Иконка ветки
  
- **Секция: Фокусные области**
  - Области для развития
  - Приоритет (высокий/средний/низкий)
  
- **Кнопки действий:**
  - "Сгенерировать квесты" (основная)
  - "Просмотреть дерево способностей"
  - "Добавить еще одну запись"

**Действия пользователя:**
- Просматривает результаты анализа
- Изучает инсайты и паттерны
- Просматривает сигналы способностей
- Нажимает "Сгенерировать квесты"

**Что происходит:**
- Система генерирует квесты на основе анализа
- Пользователь перенаправляется на `/quests` с уведомлением: "Создано X квестов"

---

### Сценарий 2: Работа с квестами

#### Шаг 1: Доска квестов (`/quests`)
**Что видит пользователь:**

**Фильтры:**
- Статус: Все / Активные / Backlog / Выполненные / Архив
- Тип: Все / Micro / Weekly / Story / In-person
- Ветка способностей: Все / Субъектность / Архитектурное мышление / ...
- Теги

**Список квестов (карточки):**
Каждая карточка содержит:
- **Заголовок:** Название квеста
- **Тип:** Бейдж (Micro / Weekly / Story / In-person)
- **Описание:** Краткое описание (1-2 предложения)
- **Прогресс:**
  - Прогресс-бар выполнения
  - Текст: "2 из 3 шагов выполнено"
- **Связанные способности:**
  - Иконки веток
  - Названия узлов
- **Награда:**
  - XP: 100
  - Skill XP: +50 к "Контейнирование"
- **Статус:** Бейдж (Активный / Backlog / Выполнен)
- **Дедлайн:** (если есть)
- **Кнопки:**
  - "Открыть" (основная)
  - "Активировать" (если в backlog)
  - "Завершить" (если выполнены критерии)

**Действия пользователя:**
- Просматривает список квестов
- Фильтрует по статусу/типу/ветке
- Выбирает квест и нажимает "Открыть"

**Что происходит:**
- Переход на детальную страницу квеста

---

#### Шаг 2: Детали квеста (`/quests/[id]`)
**Что видит пользователь:**

**Заголовок:**
- Название квеста
- Тип (бейдж)
- Статус (бейдж)

**Описание:**
- Полное описание квеста
- Контекст и цель

**Шаги выполнения:**
Список шагов с чекбоксами:
- [✓] Шаг 1: Определите ситуацию с напряжением (выполнено)
- [ ] Шаг 2: Сделайте паузу и наблюдайте (в процессе)
- [ ] Шаг 3: Запишите наблюдения (не начато)

Каждый шаг:
- Название
- Описание
- Статус (выполнено/в процессе/не начато)
- Кнопка "Отметить выполненным"

**Критерии успеха:**
- Список критериев
- Прогресс по каждому критерию

**Связанные способности:**
- Карточки узлов дерева:
  - Название узла
  - Ветка
  - Текущий прогресс (XP)
  - Ссылка "Подробнее о способности"

**Награды:**
- XP: 100
- Skill XP: +50 к "Контейнирование"
- Прогресс по узлам

**Доказательства:**
- Список прикрепленных Evidence
- Кнопка "Добавить доказательство"

**Действия:**
- Кнопки:
  - "Начать выполнение" (если не начат)
  - "Добавить доказательство"
  - "Отметить шаг выполненным"
  - "Завершить квест" (если выполнены критерии)
  - "Перевести в backlog" (если активен)

**Действия пользователя:**
- Изучает описание и шаги
- Начинает выполнение
- Отмечает выполненные шаги
- Добавляет доказательства
- Завершает квест

**Что происходит:**
- При отметке шага обновляется прогресс
- При добавлении доказательства создается Evidence
- При завершении квеста:
  - Начисляется XP
  - Обновляется прогресс узлов
  - Квест переводится в статус "done"
  - Проверяется разблокировка новых узлов

---

#### Шаг 3: Добавление доказательства (`/evidence/new?quest_id=[id]`)
**Что видит пользователь:**
- Форма:
  - Тип: ситуация / наблюдение / рефлексия / обратная связь
  - Текст (textarea)
  - Связанный квест (предзаполнено)
  - Связанные способности (multi-select)
  - Теги
  - Файлы (опционально)
- Кнопки:
  - "Сохранить"
  - "Отмена"

**Действия пользователя:**
- Заполняет форму
- Прикрепляет файлы (если нужно)
- Нажимает "Сохранить"

**Что происходит:**
- Evidence сохраняется
- Связывается с квестом и способностями
- Обновляется прогресс квеста
- Перенаправление на детали квеста

---

### Сценарий 3: Просмотр дерева способностей

#### Шаг 1: Дерево способностей (`/tree`)
**Что видит пользователь:**

**Визуализация дерева:**
- Интерактивный граф (React Flow)
- 6 веток (разные цвета)
- Узлы способностей:
  - Цвет по статусу:
    - Серый: заблокирован
    - Синий: доступен
    - Зеленый: активен
    - Золотой: разблокирован
    - Фиолетовый: интегрирован
  - Размер по уровню (basic/intermediate/advanced)
  - Прогресс-бар XP

**Легенда:**
- Статусы узлов
- Уровни (basic/intermediate/advanced)
- Уровни интеграции (Novice/Integrated/Embodied)

**Фильтры:**
- Ветка: Все / Субъектность / Архитектурное мышление / ...
- Статус: Все / Заблокированные / Доступные / Активные / Разблокированные
- Уровень: Все / Basic / Intermediate / Advanced

**Действия:**
- Клик на узел → открывает детали узла
- Клик на ветку → фильтрует по ветке
- Zoom in/out
- Панорамирование

**Действия пользователя:**
- Просматривает дерево
- Изучает прогресс
- Кликает на интересующий узел

**Что происходит:**
- Открывается модальное окно или переход на `/tree/nodes/[id]`

---

#### Шаг 2: Детали узла (`/tree/nodes/[id]`)
**Что видит пользователь:**

**Информация об узле:**
- Название
- Ветка (с иконкой и цветом)
- Уровень (basic/intermediate/advanced)
- Статус
- Уровень интеграции

**Описание:**
- Полное описание способности
- Практическое значение
- Примеры применения
- Уровни интеграции (Novice/Integrated/Embodied)

**Прогресс:**
- Текущий XP: 150 / 200
- Прогресс-бар
- Осталось до разблокировки: 50 XP

**Связанные квесты:**
- Список квестов, связанных с этим узлом
- Фильтр: Все / Доступные / Активные / Выполненные
- Кнопка "Начать квест" для каждого

**Условия разблокировки:**
- Требования (если есть)
- Предварительные узлы (если есть)

**История развития:**
- Timeline с записями о применении способности
- Связанные Evidence
- Сессии, где проявилась способность

**Действия:**
- Кнопки:
  - "Начать квест для развития" (если есть доступные)
  - "Просмотреть связанные квесты"
  - "Добавить доказательство применения"

**Действия пользователя:**
- Изучает описание
- Просматривает прогресс
- Выбирает квест для развития
- Просматривает историю

**Что происходит:**
- При выборе квеста переход на `/quests/[id]`
- При добавлении доказательства переход на `/evidence/new`

### Сценарий 5: Ежедневный цикл

#### Утро: Планирование дня
**Действия пользователя:**
1. Открывает `/dashboard`
2. Просматривает активные квесты
3. Выбирает квест на день
4. Планирует действия

**Что происходит:**
- Пользователь готов к практике

---

#### В течение дня: Выполнение
**Действия пользователя:**
1. Встречает ситуацию для практики
2. Открывает приложение (мобильное или веб)
3. Открывает активный квест
4. Отмечает выполненный шаг
5. Добавляет краткую заметку

**Что происходит:**
- Обновляется прогресс квеста
- Сохраняется заметка

---

#### Вечер: Рефлексия
**Действия пользователя:**
1. Открывает `/entries/new`
2. Создает запись о дне:
   - Что произошло
   - Какие способности применил
   - Что получилось, что нет
   - Инсайты
3. Нажимает "Сохранить и проанализировать"
4. Просматривает результаты анализа
5. Создает квесты на основе анализа (опционально)

**Что происходит:**
- Создается запись
- Запускается анализ
- Генерируются инсайты
- Предлагаются квесты

---

### Сценарий 6: Недельный цикл

#### Понедельник: Планирование недели
**Действия пользователя:**
1. Открывает `/dashboard`
2. Просматривает прогресс по веткам
3. Выбирает фокусную область на неделю
4. Активирует weekly квест
5. Планирует действия на неделю

**Что происходит:**
- Weekly квест активирован
- Пользователь готов к недельной практике

---

#### Среда: Промежуточная проверка
**Действия пользователя:**
1. Открывает `/quests?status=active&type=weekly`
2. Просматривает прогресс по weekly квесту
3. Добавляет доказательства
4. Корректирует план (если нужно)

**Что происходит:**
- Обновляется прогресс
- Сохраняются доказательства

---

#### Пятница: Недельная рефлексия
**Действия пользователя:**
1. Открывает `/entries/new`
2. Создает запись о неделе:
   - Что произошло за неделю
   - Какие способности практиковал
   - Что получилось, что нет
   - Инсайты о развитии
3. Завершает weekly квест
4. Просматривает прогресс
5. Планирует следующую неделю

**Что происходит:**
- Создается запись
- Weekly квест завершен
- Начисляется XP
- Обновляется прогресс узлов

## 🎮 Ключевые точки взаимодействия

### 1. Создание записи → Анализ → Квесты
**Цель:** Превратить опыт в практику
**Flow:**
1. Описать ситуацию
2. Получить анализ
3. Получить квесты для развития
4. Начать практику

### 2. Квест → Практика → Доказательства → Прогресс
**Цель:** Структурированная практика
**Flow:**
1. Выбрать квест
2. Выполнить шаги
3. Добавить доказательства
4. Получить прогресс

### 3. Дерево → Узел → Квесты → Практика
**Цель:** Целенаправленное развитие
**Flow:**
1. Выбрать способность для развития
2. Изучить описание
3. Найти связанные квесты
4. Начать практику

### 4. Dashboard → Обзор → Действия
**Цель:** Видеть общую картину и действовать
**Flow:**
1. Просмотреть статистику
2. Увидеть прогресс
3. Выбрать действие
4. Начать практику

- Количество разблокированных узлов

- Регулярность использования (ежедневно/еженедельно)

- Продолжительность сессий

1. Начало месяца: Обзор прогресса

## 🎯 Цели пользователя на разных этапах

### Новичок (первые 2 недели):
- Понять систему
- Создать первые записи
- Выполнить первые квесты
- Разблокировать первые узлы

### Активный пользователь (1-3 месяца):
- Регулярно создавать записи
- Выполнять квесты разных типов
- Развивать способности целенаправленно
- Интегрировать практику в ежедневную жизнь

### Продвинутый пользователь (3+ месяца):
- Глубоко развивать способности
- Создавать собственные практики
- Влиять на культуру команды/организации
- Достигать уровней интеграции (Integrated/Embodied)
