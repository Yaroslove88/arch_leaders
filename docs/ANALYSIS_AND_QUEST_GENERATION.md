# Анализ записей и генерация квестов

## Обзор процесса

Система анализирует записи пользователя (Entry) и автоматически создаёт квесты для развития выявленных способностей.

**Процесс:**
1. **Entry** → Пользователь создаёт запись (ситуация, рефлексия)
2. **Analysis** → LLM анализирует запись и извлекает структурированные данные
3. **Quest Generation** → На основе анализа создаются квесты через QuestEngine
4. **Quest Theory** → Для каждого квеста генерируется теория и примеры через LLM

## 1. Анализ записей (Entry → Session)

### Что извлекается из записи

При анализе записи система извлекает следующие данные:

#### 1.1 Темы (Themes)
- **Что это:** Повторяющиеся мотивы, ключевые темы ситуации
- **Формат:** Массив строк
- **Пример:** `["делегирование", "обратная связь", "конфликт в команде"]`
- **Использование:** Для генерации story-квестов (главная тема)

#### 1.2 Паттерны (Patterns)
- **Что это:** Поведенческие паттерны лидера, которые проявились в ситуации
- **Формат:** Массив строк
- **Пример:** `["избегание конфликтов", "микроменеджмент", "недостаточное делегирование"]`
- **Использование:** Для понимания контекста и генерации квестов

#### 1.3 Напряжения (Tensions)
- **Что это:** Конфликты, противоречия, точки напряжения в ситуации
- **Формат:** Массив строк
- **Пример:** `["конфликт между отделами", "несоответствие ожиданий и реальности"]`
- **Использование:** Для выявления зон развития

#### 1.4 Способности (Ability Signals)
- **Что это:** Проявленные архитектурные способности из дерева способностей
- **Формат:** Массив объектов `{node_id: string, signal: string}`
- **Пример:** `[{"node_id": "delegation_001", "signal": "попытка делегировать, но недостаточно доверия"}]`
- **Использование:** Для генерации micro-квестов (основной источник)

#### 1.5 Инсайты (Insights)
- **Что это:** Важные наблюдения, ключевые моменты ситуации
- **Формат:** Массив объектов `{title: string, description: string}`
- **Пример:** `[{"title": "Недостаток доверия", "description": "Лидер не доверяет команде выполнение задач"}]`
- **Использование:** Для контекста и понимания ситуации

#### 1.6 Фокус (Focus)
- **Что это:** Зоны для внимания, приоритетные области развития
- **Формат:** Массив объектов `{area: string, priority: "high" | "medium" | "low"}`
- **Пример:** `[{"area": "делегирование", "priority": "high"}]`
- **Использование:** Для генерации weekly-квестов (high priority focus)

### Промпт для анализа

**ID:** `analysis_situation`  
**Purpose:** `extract`  
**Версия:** 1

Промпт находится в `prompt_registry` и используется в `LLMService.analyzeSituation()`.

**Структура промпта:**
- Описание задачи анализа
- Инструкции по извлечению данных
- Формат JSON ответа
- Примеры структуры данных

## 2. Генерация квестов (Session → Quests)

### Правила генерации (QuestEngine)

Квесты генерируются детерминированно на основе правил в `QuestEngine`:

#### 2.1 Micro-квесты (из Ability Signals)
- **Источник:** `ability_signals` из анализа
- **Тип:** `micro`
- **Критерии:** `evidence` (3 доказательства применения способности)
- **Награда:** 100 XP базовых + 50 XP способности
- **Максимум:** 10 квестов из ability signals

**Логика:**
- Для каждого ability signal создаётся квест на развитие соответствующей способности
- Квест привязан к узлу способности (`linked_nodes`)
- Критерии: собрать 3 доказательства применения способности

#### 2.2 Weekly-квесты (из Focus)
- **Источник:** `focus` с `priority: "high"` из анализа
- **Тип:** `weekly`
- **Критерии:** `count` (5 применений)
- **Награда:** 200 XP базовых + 100 XP способности
- **Максимум:** 3 квеста из focus

**Логика:**
- Для каждого high-priority focus создаётся квест
- Фокус на практическом применении в течение недели
- Критерии: применить способность 5 раз

#### 2.3 Story-квесты (из Themes)
- **Источник:** Главная тема из `themes` (первая тема)
- **Тип:** `story`
- **Критерии:** `custom` (специфичные для темы)
- **Награда:** 300 XP базовых
- **Максимум:** 1 квест из главной темы

**Логика:**
- Создаётся один комплексный квест на основе главной темы
- Квест может быть связан с несколькими способностями
- Критерии определяются специфично для темы

#### 2.4 In-person квесты (из анализа)
- **Источник:** Анализ ситуации через Core Loop
- **Тип:** `in-person`
- **Особенность:** Индивидуальные квесты для каждого пользователя
- **Создание:** Автоматически при анализе ситуации через `CoreLoopService.process()`

**Логика:**
- Создаётся на основе анализа конкретной ситуации пользователя
- Связан с `session_id` (источник анализа)
- Критерии определяются на основе выявленных способностей и тем

### Структура квеста

```typescript
{
  userId: string;
  title: string;
  description: string;
  type: 'micro' | 'weekly' | 'story' | 'in-person';
  criteria: {
    type: 'evidence' | 'count' | 'custom';
    target: number; // для evidence/count
    description: string;
    theory_and_examples: string; // генерируется через LLM
  };
  reward: {
    base_xp: number;
    skill_xp?: number;
  };
  linked_nodes: string[]; // ID узлов способностей
  session_id?: string; // для in-person квестов
  source: 'session_analysis' | 'core-loop' | 'base_template';
  tags: string[];
  rationale: Rationale; // объяснение почему создан квест
}
```

## 3. Генерация теории квестов (Quest → Theory)

### Промпт для теории

**ID:** `quest_theory`  
**Purpose:** `quest_generate`  
**Версия:** 1

Промпт находится в `prompt_registry` и используется в `LLMService.generateQuestTheory()`.

**Что генерируется:**
1. **Теоретическое объяснение способности**
   - Что это за способность и почему важна
   - Связь с другими способностями
   - Место в развитии лидера

2. **Практическое значение**
   - Как способность проявляется в реальных ситуациях
   - Что делать и чего избегать
   - Типичные ошибки

3. **Примеры применения**
   - 2-3 реальных примера ситуаций
   - Примеры "хорошо" и "плохо"
   - Примеры из разных контекстов

4. **Практические советы**
   - Как начать практиковать
   - С чего начать
   - Как заметить прогресс
   - Что делать при трудностях

5. **Интеграция в практику**
   - Как сделать частью ежедневной практики
   - Когда и где практиковать
   - Как отслеживать применение

**Формат:** Markdown текст (800-1200 слов)

## 4. Поток данных

```
Entry (текст ситуации)
  ↓
LLMService.analyzeSituation()
  ↓ (использует промпт analysis_situation)
Session (структурированные данные)
  ↓
QuestGenerationService.generateQuests()
  ↓ (использует QuestEngine для правил)
GeneratedQuest[] (структура квестов)
  ↓
LLMService.generateQuestTheory()
  ↓ (использует промпт quest_theory)
Quest (с теорией и примерами)
  ↓
QuestsService.create()
  ↓
Quest в БД
```

## 5. Промпты в системе

Все промпты хранятся в таблице `prompt_registry`:

- **prompt_id** — уникальный идентификатор промпта
- **version** — версия промпта
- **status** — `draft` | `active` | `deprecated`
- **purpose** — `extract` | `quest_generate` | `summarize` | и т.д.
- **template** — шаблон промпта (может содержать переменные)
- **schema** — JSON схема ожидаемого ответа

### Текущие промпты

1. **analysis_situation** (v1, active)
   - Анализ управленческих ситуаций
   - Извлечение тем, паттернов, способностей

2. **quest_theory** (v1, active)
   - Генерация теории и примеров для квестов
   - Подробное объяснение способностей

## 6. Использование промптов в коде

### LLMService

```typescript
// Анализ ситуации
const result = await llmService.analyzeSituation(entry);
// Использует промпт analysis_situation из prompt_registry

// Генерация теории квеста
const theory = await llmService.generateQuestTheory(quest, abilityNode);
// Использует промпт quest_theory из prompt_registry
```

**Примечание:** В текущей реализации промпты хардкодятся в `LLMService`, но должны загружаться из `prompt_registry` для версионирования и управления.

## 7. Что нужно извлечь из записи

### Обязательные данные

1. **Темы** — для story-квестов
2. **Ability Signals** — для micro-квестов (основной источник)
3. **Focus (high priority)** — для weekly-квестов

### Дополнительные данные

4. **Паттерны** — для контекста
5. **Напряжения** — для понимания проблем
6. **Инсайты** — для понимания ситуации

## 8. Как создаются квесты

### Детерминированные правила (QuestEngine)

- Одинаковые входные данные = одинаковый результат
- Не зависит от времени выполнения
- Не делает запросов к БД или LLM (чистая функция)
- Определяет структуру квестов, критерии, награды

### LLM-генерация

- **Теория квестов** — генерируется через LLM для каждого квеста
- **Зависит от:** типа квеста, связанных способностей, контекста

## 9. Индивидуальность квестов

- **In-person квесты** создаются индивидуально для каждого пользователя на основе его конкретной ситуации
- **Базовые квесты** (micro/weekly/story) могут быть общими, но привязываются к конкретным способностям пользователя
- **Теория квестов** генерируется индивидуально с учётом контекста способности и типа квеста
