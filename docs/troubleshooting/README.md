## Логика именования файлов

Все файлы документации по troubleshooting именуются по следующей логике:

```
<TЕМА>_<ТИП>.md
```

**Где:**
- `<ТЕМА>` — тема документа (ERROR, TROUBLESHOOTING, SWAGGER, BUILDS, TREE_SERVICE, PRISMA, SYNC)
- `<ТИП>` — тип документа (FIX, HANDLING_GUIDE, PATTERNS_ANALYSIS, RESOLUTION, COMPLETE)

## Быстрый старт

1. **При возникновении проблемы:**
   - Начните с [TROUBLESHOOTING.md](./TROUBLESHOOTING.md)

2. **Для понимания обработки ошибок:**
   - Изучите [ERROR_HANDLING_GUIDE.md](./ERROR_HANDLING_GUIDE.md)

3. **Для анализа паттернов ошибок:**
   - См. [ERROR_PATTERNS_ANALYSIS.md](./ERROR_PATTERNS_ANALYSIS.md)

---

## Обновление документации

При обнаружении новых проблем:

- **Добавьте решение** в `TROUBLESHOOTING.md`
- **Задокументируйте паттерн** в `ERROR_PATTERNS_ANALYSIS.md`
- **Обновите руководство** в `ERROR_HANDLING_GUIDE.md`
