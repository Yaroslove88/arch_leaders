## Формула ранжирования

Кейсы сортируются по следующему приоритету:

1. **Решённые кейсы** → перемещаются в конец списка
2. **Уровень узла** → сначала уровень 1, затем уровень 2
3. **ID узла** → группировка по узлам (алфавитный порядок)
4. **Сложность** → внутри узла: basic → intermediate → advanced

## Анализ логики ранжирования и исправленных проблем

### Общая логика ранжирования

Кейсы сортируются по следующему приоритету (в порядке убывания приоритета):

1. **Решённые кейсы** → перемещаются в конец списка
   - Сортировка: `isSolved` (false < true)
   - Код: `return a.isSolved ? 1 : -1;`

2. **Уровень узла** → сначала уровень 1, затем уровень 2
   - Сортировка: по возрастанию (1 < 2)
   - Код: `return a.nodeLevel - b.nodeLevel;`

3. **ID узла** → группировка по узлам в алфавитном порядке
   - Сортировка: по возрастанию (алфавитный порядок строк)
   - Код: `return (a.nodeId || '').localeCompare(b.nodeId || '');`

4. **Сложность** → внутри узла: basic → intermediate → advanced
   - Сортировка: по возрастанию порядка сложности (1 < 2 < 3)
   - Код: `return a.difficultyOrder - b.difficultyOrder;`
   - Где: `basic = 1`, `intermediate = 2`, `advanced = 3`

### Где была нарушена логика и почему

**ПРОБЛЕМА (исправлена):** Логика проверки в функции `generateReport` неправильно интерпретировала результаты сортировки.

#### Суть проблемы

**Фактическая сортировка кейсов работала ПРАВИЛЬНО** - код сортировки в функции `rankCases` был корректен. Однако функция генерации отчета содержала ошибочную логику проверки, которая:

1. **Неправильно интерпретировала порядок сложности внутри узла:**
   - Когда кейсы из одного узла шли в правильном порядке (basic → intermediate → advanced), проверка помечала это как ошибку (❌)
   - Пример: позиция 2 (intermediate) после позиции 1 (basic) - это ПРАВИЛЬНО, но проверка говорила "должно быть ниже"

2. **Не учитывала контекст при проверке:**
   - Проверка сложности выполнялась без учета того, что сравнение по сложности имеет смысл только внутри одного узла
   - Проверка не различала случаи "разные узлы" и "одинаковые узлы"

#### Причина ошибки

Оригинальная логика проверки (строки 195-198 в старой версии):

```typescript
} else if (info.difficultyOrder > prev.difficultyOrder) {
    report += `- ❌ Сложность ${info.case.difficulty} > ${prev.case.difficulty} (должно быть ниже)\n\n`;
}
```

Проблема: эта проверка не учитывала, что:
- Если текущий кейс стоит **после** предыдущего (большая позиция) и имеет большую сложность **внутри одного узла**, это **правильно**
- Проверка должна была быть только для случая, когда `nodeId` одинаковые

#### Исправление

Исправленная логика проверки:

```typescript
} else if (info.nodeId !== prev.nodeId) {
    // Разные узлы - проверяем алфавитный порядок
    if (info.nodeId < prev.nodeId) {
        report += `- ❌ node_id "${info.nodeId}" < "${prev.nodeId}" (должно быть выше в списке, т.к. алфавитный порядок)\n\n`;
    } else {
        report += `- ✅ node_id "${info.nodeId}" > "${prev.nodeId}" (правильный алфавитный порядок)\n\n`;
    }
} else {
    // Одинаковые узлы - проверяем сложность (должна быть по возрастанию)
    if (info.difficultyOrder < prev.difficultyOrder) {
        report += `- ❌ Сложность ${info.case.difficulty} (${info.difficultyOrder}) < ${prev.case.difficulty} (${prev.difficultyOrder}) (должно быть выше, т.к. basic → intermediate → advanced)\n\n`;
    } else if (info.difficultyOrder > prev.difficultyOrder) {
        report += `- ✅ Сложность ${info.case.difficulty} (${info.difficultyOrder}) > ${prev.case.difficulty} (${prev.difficultyOrder}) (правильный порядок: basic → intermediate → advanced)\n\n`;
    }
}
```

#### Результат исправления

Теперь отчет правильно показывает:
- ✅ Правильную сортировку по сложности внутри узла (basic → intermediate → advanced)
- ✅ Правильную сортировку по ID узла в алфавитном порядке
- ✅ Правильную проверку всех факторов ранжирования с учетом контекста

### Итоговый вывод

**Логика сортировки была правильной с самого начала** - проблема была только в логике проверки и генерации отчета. После исправления все проверки работают корректно, и отчет правильно отражает фактическое состояние ранжирования кейсов.
