## Полная карточка кейса (страница детального просмотра)

### ✅ Что работает хорошо

1. **Название кейса** — отображается корректно
2. **Отдельное поле контекста** — структурированно с секциями (Компания, Проект, Ситуация и т.д.)
3. **Варианты действий визуально хорошо выделяются**
   - Буквенные индикаторы (A, B, C, D) в цветных кружочках
   - Градиентный фон
   - Хорошие hover-эффекты
4. **Варианты действий содержат только варианты ответов БЕЗ технической информации**
   - Навыки, последствия, влияние на систему скрыты до выбора
5. **При выборе ответа визуально всё красиво**
   - Структурированное отображение последствий
   - Цветные акценты для разных типов эффектов
   - Влияние на систему в виде цветных бейджей

### ❌ Что нужно исправить

1. **Ключевые слова не выделены жирным**
   - Компания, Проблема, Последний инцидент и другие важные термины из исходного документа были выделены жирным
   - Сейчас они не выделены, визуально плохо воспринимаются
   - **Требование**: Важные термины и ключевые слова должны быть выделены жирным шрифтом или другим визуальным акцентом

2. **Цифры выделены цветом, который сливается с фоном**
   - Цифры выделяются синим цветом (`text-system-focus`), который плохо виден на фоне
   - **Требование**: Цифры должны быть выделены контрастным цветом, хорошо читаемым на фоне

3. **Цифры перекрашиваются без логики и местами неуместно**
   - Пример: "B2B" — буквы "2B" перекрашиваются как цифра
   - **Требование**: Регулярное выражение для выделения цифр должно быть более точным, чтобы не захватывать буквы в составе слов

4. **Навыки периодически на английском**
   - После выбора ответа в поле "Навык" иногда отображается английское название
   - **Требование**: Все навыки должны отображаться на русском языке
   - **Решение**: Навыки - это названия узлов, поэтому используется `getNodeName()` для получения русского названия узла
   - Для навыков, которые не являются узлами напрямую, используется fallback маппинг

## Технические требования

### Структура данных кейса

```typescript
interface InteractiveCase {
  id: string;
  title: string;
  summary?: string; // НОВОЕ: Краткое описание для карточки (1-2 предложения)
  node_id?: string;
  branch_id?: string;
  difficulty: 'basic' | 'intermediate' | 'advanced';
  context: string; // Полное описание с секциями
  // ... остальные поля
}
```

### Форматирование контекста

- Секции должны быть визуально выделены
- Ключевые слова (Компания, Проблема, Инцидент и т.д.) должны быть жирными
- Цифры должны выделяться контрастным цветом
- Регулярное выражение для цифр: `/\b\d+\b/g` (только целые числа, не часть слова)

### Переводы

- Все названия узлов должны быть на русском
- **Навыки - это названия узлов**, поэтому используются названия узлов из `nodeNameMap` и `nodeDescriptions`
- Функция `translateSkill()` преобразует название навыка в `node_id` и использует `getNodeName()` для получения русского названия
- Для навыков, которые не являются узлами напрямую, используется fallback маппинг `skillFallbackMap`
- Проверить, что все узлы из `nodeNameMap` имеют русские названия
