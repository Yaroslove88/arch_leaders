# Правила архитектуры: Единый источник истины

**Дата создания:** 2025-01-27  
**Статус:** Этап 1 - Аудит и документация

---

## Принципы

### 1. Единый источник истины (Single Source of Truth, SSOT)

**Правило:** Каждый тип данных должен иметь один и только один источник истины.

**Применение:**
- **Структура** → `initial-ability-tree.json` (seed файл)
- **Контент** → `data/node-descriptions.json` (для узлов)
- **Теоретическая база** → `data/theory-base/` (научная база, методология)
- **Пользовательские данные** → БД таблицы (`UserAbilityState`, `Quest`, `Entry`, `Session`)

**Запрещено:**
- ❌ Дублировать контент в нескольких местах
- ❌ Смешивать структуру, контент и пользовательские данные в одном месте
- ❌ Хранить пользовательские данные в seed файлах или контентных файлах

---

## 2. Разделение ответственности

### 2.1. Структура (неизменяемая база)

**Что входит:**
- `node_id`, `branch_id`, `tier`
- `prerequisites` (массив node_id)
- `unlock_conditions` (структура условий)
- `xp_required` (базовое значение)

**Где хранится:**
- `packages/shared/src/seed/initial-ability-tree.json` (источник истины)
- `TreeSemantic.data` в БД (только структура, без контента и пользовательских данных)

**Правила обновления:**
- ✅ Обновляется только при изменении структуры (добавление/удаление узлов)
- ✅ Обновление seed файла обновляет только структуру в БД
- ❌ Не содержит контент (name, description)
- ❌ Не содержит пользовательские данные (state, xp_current)

### 2.2. Контент (переводы, описания)

**Что входит:**
- `name` (русское название)
- `full_description`, `practical_meaning`
- `examples` (массив примеров)
- `integration_levels` (описания уровней)
- `reflection_prompts` (вопросы для рефлексии)

**Где хранится:**
- `data/node-descriptions.json` (источник истины для узлов)
- `data/quest-templates.json` (источник истины для базовых квестов)
- `data/interactive-cases.json` (источник истины для кейсов)
- `data/builds.json` (источник истины для стилей лидерства)

**Правила обновления:**
- ✅ Обновляется независимо от структуры
- ✅ Не хранится в БД (загружается из файлов)
- ✅ Кэшируется в памяти для производительности
- ❌ Не смешивается со структурой или пользовательскими данными

### 2.3. Теоретическая база (научная база, методология)

**Что входит:**
- Теория лидерства
- Теория по каждой ветке развития
- Методология рефлексии
- Теория развития (вертикальное развитие, DDO)
- Научная база курса

**Где хранится:**
- `data/theory-base/` (структура файлов)
  - `leadership/` - теория лидерства
  - `branches/` - теория по веткам развития
  - `methodology/` - методология
  - `reflection/` - методология рефлексии
  - `development/` - теория развития

**Правила использования:**
- ✅ Используется для обогащения контента через LLM
- ✅ Системные промпты привязаны к теоретической базе
- ✅ LLM работает только в рамках теоретической базы (не фантазирует)
- ❌ Не хранится в БД

### 2.4. Пользовательские данные (уникальны для каждого пользователя)

**Что входит:**
- Прогресс по узлам (`state`, `xp_current`, `progress`, `relevance`)
- Пользовательские квесты (source='user_generated' или 'auto_generated')
- Записи пользователя (`Entry`, `Session`, `Evidence`)
- Прогресс по кейсам (`CaseProgress`)

**Где хранится:**
- `UserAbilityState` (таблица в БД) - прогресс по узлам
- `Quest` (таблица в БД) - квесты пользователя
- `Entry`, `Session`, `Evidence` (таблицы в БД) - записи и анализ
- `CaseProgress` (таблица в БД) - прогресс по кейсам

**Правила обновления:**
- ✅ Обновляется только через действия пользователя
- ✅ Не перезаписывается при обновлении seed файла
- ✅ Не перезаписывается при обновлении контента
- ❌ Не хранится в seed файлах или контентных файлах
- ❌ Не смешивается со структурой или контентом

## 3. Правила обновления данных

### 3.1. Обновление структуры (seed файл)

**Когда:** При изменении структуры дерева (добавление/удаление узлов, изменение prerequisites)

**Процесс:**
1. Обновить `initial-ability-tree.json` (только структура, без контента)
2. Увеличить `tree_revision` в seed файле
3. При запуске системы:
   - Проверить `seedRevision > dbRevision`
   - Если да, обновить только структуру в `TreeSemantic.data`
   - **НЕ** обновлять контент или пользовательские данные

**Код:**
```typescript
// ✅ ПРАВИЛЬНО: Обновляет только структуру
if (seedRevision > dbRevision) {
  const structureOnly = this.extractStructure(normalizedSeedData);
  await this.prisma.treeSemantic.upsert({
    update: {
      data: structureOnly as any,  // Только структура
    },
  });
}
```

**Запрещено:**
- ❌ Обновлять контент из seed файла
- ❌ Обновлять пользовательские данные из seed файла
- ❌ Перезаписывать всё поле `data` целиком

### 3.2. Обновление контента

**Когда:** При изменении переводов, описаний, примеров

**Процесс:**
1. Обновить соответствующий JSON файл (`node-descriptions.json`, `quest-templates.json`, etc.)
2. Контент загружается из файлов при запросе (не хранится в БД)
3. Можно обновить кэш в памяти, если используется

**Запрещено:**
- ❌ Обновлять контент из seed файла
- ❌ Хранить контент в БД (кроме кэша)
- ❌ Смешивать контент со структурой или пользовательскими данными

### 3.3. Обновление пользовательских данных

**Когда:** Только через действия пользователя

**Процесс:**
1. Пользователь выполняет действие (разблокирует узел, создает квест, добавляет запись)
2. Обновляется соответствующая таблица в БД
3. Данные сохраняются только в таблицах пользовательских данных

**Запрещено:**
- ❌ Обновлять пользовательские данные из seed файла
- ❌ Обновлять пользовательские данные из контентных файлов
- ❌ Перезаписывать пользовательские данные при обновлении структуры или контента

### 3.4. Обновление базовых квестов

**Когда:** При изменении шаблонов квестов в `quest-templates.json`

**Процесс:**
1. Обновить `quest-templates.json`
2. Запустить `sync-base-quests.ts`
3. Скрипт обновляет только квесты с `source='base_template'`
4. Не затрагивает квесты с `source='user_generated'` или `source='auto_generated'`

**Код:**
```typescript
// ✅ ПРАВИЛЬНО: Обновляет только base_template квесты
const existing = await prisma.quest.findFirst({
  where: { 
    title: title,
    source: 'base_template'  // Только базовые квесты
  }
});

if (existing) {
  await prisma.quest.update({
    where: { id: existing.id },
    data: questData
  });
}
```

**Запрещено:**
- ❌ Обновлять квесты по `title` без проверки `source`
- ❌ Перезаписывать пользовательские квесты (`source='user_generated'`)
- ❌ Перезаписывать автоматически сгенерированные квесты (`source='auto_generated'`)

## 4. Правила объединения данных

### 4.1. Объединение происходит только в runtime

**Правило:** Данные объединяются только при запросе, не сохраняются в БД.

**Процесс:**
1. Загрузить структуру из `TreeSemantic.data` (или seed)
2. Загрузить контент из `node-descriptions.json`
3. Загрузить пользовательские данные из `UserAbilityState`
4. Объединить в памяти
5. Вернуть объединенный результат
6. **НЕ** сохранять объединенный результат в БД

**Код:**
```typescript
// ✅ ПРАВИЛЬНО: Объединение в runtime
async getSemantic(userId?: string): Promise<SemanticTree> {
  // 1. Загружаем структуру
  const structure = await this.loadStructure();
  
  // 2. Загружаем контент
  const content = await this.loadContent();
  
  // 3. Загружаем пользовательские данные
  const userData = userId ? await this.loadUserData(userId) : null;
  
  // 4. Объединяем в runtime (не сохраняем в БД!)
  return this.mergeData(structure, content, userData);
}
```

**Запрещено:**
- ❌ Сохранять объединенный результат в БД
- ❌ Смешивать структуру, контент и пользовательские данные в одном месте хранения

## 5. Защита от перезаписи

### 5.1. Защита пользовательских данных

**Правило:** Пользовательские данные никогда не перезаписываются при обновлении структуры или контента.

**Реализация:**
1. Пользовательские данные хранятся отдельно (в таблицах БД)
2. При обновлении seed файла обновляется только структура
3. При обновлении контента обновляются только контентные файлы
4. Пользовательские данные не затрагиваются

### 5.2. Защита пользовательских квестов

**Правило:** Пользовательские квесты не перезаписываются при синхронизации базовых квестов.

**Реализация:**
1. Все квесты имеют поле `source`:
   - `'base_template'` - базовые квесты из шаблонов
   - `'auto_generated'` - автоматически сгенерированные квесты
   - `'user_generated'` - квесты, созданные пользователем
2. `sync-base-quests.ts` обновляет только квесты с `source='base_template'`
3. Проверка перед обновлением:
   ```typescript
   if (existing.source !== 'base_template') {
     // Не обновляем пользовательские квесты
     return;
   }
   ```

### 5.3. Валидация перед обновлением

**Правило:** Перед обновлением данных проверять, что обновление не затронет пользовательские данные.

**Реализация:**
1. Валидация при обновлении `TreeSemantic.data`:
   - Проверить, что обновляется только структура
   - Не обновлять поля, содержащие контент или пользовательские данные
2. Валидация при обновлении квестов:
   - Проверить `source` перед обновлением
   - Не обновлять квесты с `source='user_generated'` или `source='auto_generated'`

## 6. Правила работы с теоретической базой

### 6.1. Использование теоретической базы для обогащения контента

**Правило:** При обогащении контента через LLM использовать только теоретическую базу проекта.

**Процесс:**
1. Определить, какая часть контента обогащается (examples, reflection_prompts, etc.)
2. Определить, к какой ветке/модулю относится контент
3. Загрузить соответствующую теоретическую базу
4. Выбрать подходящий системный промпт
5. Передать в LLM: промпт + теоретическая база + текущий контент
6. LLM генерирует в рамках теоретической базы
7. Валидация результата (соответствие базе, качество, форматирование)

**Запрещено:**
- ❌ Фантазировать или придумывать концепции, которых нет в теоретической базе
- ❌ Использовать внешние источники без привязки к теоретической базе

### 6.2. Системные промпты

**Правило:** Каждый системный промпт должен быть привязан к теоретической базе.

**Структура промпта:**
1. Контекст теоретической базы (какие документы использовать)
2. Четкая задача (что генерировать)
3. Ограничения (не фантазировать, работать в рамках базы)
4. Структура вывода (формат результата)
5. Примеры хорошего результата

## 7. Правила экспорта данных

### 7.1. Экспорт пользовательских данных

**Правило:** Пользователь должен иметь возможность экспортировать все свои данные.

**Что экспортируется:**
- `UserAbilityState` (прогресс по узлам)
- `Quest` (пользовательские квесты)
- `CaseProgress` (прогресс по кейсам)
- `Entry`, `Session`, `Evidence` (записи и анализ)

**Формат:** JSON файл с версионированием

**Запрещено:**
- ❌ Экспортировать структуру или контент (они не являются пользовательскими данными)

## 8. Чеклист для разработчиков

### 8.1. Перед обновлением seed файла

- [ ] Убедиться, что seed файл содержит только структуру (без контента)
- [ ] Убедиться, что seed файл не содержит пользовательских данных
- [ ] Увеличить `tree_revision` в seed файле
- [ ] Проверить, что обновление не затронет пользовательские данные

### 8.2. Перед обновлением контента

- [ ] Обновить соответствующий JSON файл (`node-descriptions.json`, etc.)
- [ ] Убедиться, что контент не смешан со структурой
- [ ] Проверить форматирование и валидность данных
- [ ] Убедиться, что обновление не затронет пользовательские данные

### 8.3. Перед обновлением квестов

- [ ] Проверить поле `source` у квестов
- [ ] Обновлять только квесты с `source='base_template'`
- [ ] Не перезаписывать пользовательские квесты
- [ ] Проверить, что обновление не затронет пользовательские данные

### 8.4. Перед созданием нового места хранения данных

- [ ] Определить тип данных (структура, контент, теоретическая база, пользовательские данные)
- [ ] Выбрать правильное место хранения согласно правилам
- [ ] Убедиться, что не дублируется существующий источник истины
- [ ] Документировать новое место хранения

## 9. Нарушения правил

### 9.1. Критические нарушения

**Нарушение:** Смешивание структуры, контента и пользовательских данных в одном месте.

**Последствия:**
- Потеря пользовательских данных при обновлении seed файла
- Перезапись русских переводов английскими
- Невозможность безопасно обновлять данные

**Решение:** Разделить данные согласно правилам архитектуры.

### 9.2. Серьезные нарушения

**Нарушение:** Дублирование контента в нескольких местах.

**Последствия:**
- Нет единого источника истины
- Конфликты при обновлении
- Сложность поддержки

**Решение:** Определить единый источник истины для каждого типа данных.

### 9.3. Умеренные нарушения

**Нарушение:** Обновление пользовательских квестов при синхронизации базовых квестов.

**Последствия:**
- Потеря пользовательских квестов
- Недовольство пользователей

**Решение:** Проверять поле `source` перед обновлением.

## 10. Мониторинг и проверка

### 10.1. Автоматические проверки

**Что проверять:**
1. `TreeSemantic.data` не содержит контент или пользовательские данные
2. Контент не дублируется в нескольких местах
3. Пользовательские данные не перезаписываются при обновлении структуры или контента
4. Квесты обновляются только с правильным `source`

**Как проверять:**
- Unit тесты для сервисов
- Интеграционные тесты для обновления данных
- Валидация перед сохранением в БД

### 10.2. Ручные проверки

**Когда проверять:**
- После обновления seed файла
- После обновления контента
- После синхронизации квестов

**Что проверять:**
- Пользовательские данные не потеряны
- Русские переводы не перезаписаны английскими
- Пользовательские квесты не перезаписаны
