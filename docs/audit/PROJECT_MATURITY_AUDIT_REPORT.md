## II. 🎯 ПРОДУКТОВАЯ СИСТЕМА

### 3. Core loop

**Статус:** 🔴 **Не реализован**

#### ✅ Что есть:
- Entry → Session (анализ работает через `AnalysisParserService`)
- Session → Quest (генерация квестов работает через `QuestGenerationService`, запускается асинхронно)
- Quest → Evidence (связь через `evidence_links_json` и `EvidenceLink`)
- Evidence → Tree Update (работает через `ChangeLog` и `TreeService.applyChange()`)
- Dashboard существует (`/dashboard`) и показывает элементы цикла, но не как единый поток

#### ❌ Что отсутствует:
- **Полный цикл НЕ проживается за один день** — нет механизма "день = цикл", нет ограничения на количество циклов в день
- **Каждый шаг не даёт ощутимую ценность** — между шагами есть разрывы, пользователь не видит немедленной пользы
- **Есть "пустые" экраны** — некоторые экраны (например, `/evidence`) не имеют смысла без следующего шага
- **Нет ощущения движения** — больше похоже на логирование отдельных событий, чем на развитие

**Проблемы:**
1. Entry создаётся отдельно (`/entries/new`), Session анализируется отдельно (`/sessions/[id]`) — нет единого потока
2. Квесты генерируются асинхронно после анализа, пользователь не видит связи в реальном времени
3. Evidence собирается отдельно (`/evidence`), обновление дерева не очевидно и не показывается сразу
4. Dashboard показывает элементы, но не показывает цикл как единое целое — нет визуализации прогресса цикла

**Рекомендации:**
1. Создать единый поток "Добавить ситуацию → Увидеть разбор → Получить квест → Зафиксировать результат" на одном экране
2. Реализовать Dashboard как центр цикла с визуализацией текущего этапа
3. Добавить визуализацию прогресса цикла (индикатор этапов)
4. Сделать каждый шаг ценным сам по себе — показывать промежуточные результаты сразу

**Оценка:** 3/10

### 4. Пользовательский путь

**Статус:** ⚠️ **Частично**

#### ✅ Что есть:
- Есть страницы: Dashboard, Entries, Sessions, Quests, Tree, Evidence
- Есть API для всех операций
- Базовая навигация работает

#### ❌ Что отсутствует:
- **Первый опыт требует обучения** — нет онбординга, пользователь попадает сразу на Dashboard без объяснений
- **Первый результат не приходит быстро** — нужно создать Entry (через модальное окно или `/entries/new`), дождаться анализа (асинхронно), найти квест в списке — процесс занимает >5 минут
- **Пользователь не понимает что произошло** — нет объяснений на каждом шаге, нет обратной связи "что система увидела"
- **Онбординг не объясняет рамку** — нет онбординга вообще, нет объяснения методологии

**Проблемы:**
1. Нет первого экрана с объяснением "что это" — пользователь сразу видит Dashboard
2. Нет быстрого способа получить первый результат (<5 мин) — требуется несколько шагов с ожиданием
3. Нет обратной связи "что система увидела" — анализ есть, но не объясняется пользователю простым языком
4. Нет объяснения "что предлагается дальше" — квесты генерируются, но не объясняется почему именно эти

**Рекомендации:**
1. Создать онбординг с объяснением рамки метода (что развивается, как работает система)
2. Реализовать "быстрый старт" — первый результат за 2-3 минуты (упрощённый поток для первого Entry)
3. Добавить объяснения на каждом экране (что произошло, что система увидела, что дальше)
4. Создать "гид по первому использованию" — интерактивный тур по основным экранам

**Оценка:** 4/10

## IV. 🧩 ИГРОВАЯ И РАЗВИВАЮЩАЯ ЛОГИКА

### 9. Дерево способностей

**Статус:** ⚠️ **Частично**

#### ✅ Что есть:
- В схеме БД есть `AbilityNode` с уровнями (`tier: 'basic|intermediate|advanced'` и `level: 'basic|mid|advanced|master'` в разных местах)
- Есть `AbilityBranch` (6 веток LEADER в seed данных)
- Есть состояния узлов (`locked|available|active|unlocked|integrated` в `UserAbilityState`)
- Есть связи через `AbilityEdge` с полем `type`, но тип не используется для различения вертикальных/диагональных/горизонтальных

#### ❌ Что отсутствует:
- **Вертикальные уровни не явны** — `tier` и `level` есть, но не используются как координаты Y в визуализации, нет явной вертикальной структуры
- **Архитектурные сцепки не реализованы** — связи через `AbilityEdge` есть, но `type` не различает "сцепки" от обычных связей
- **Всё связано со всем** — нет ограничений на количество связей, нет валидации структуры дерева
- **Нет "потолков"** — нет ограничений на развитие (можно "прокачать" всё), нет концепции потолка уровня
- **Интеграционные состояния не работают** — `integrated` есть в схеме, но логика перехода в `integrated` и влияние на систему не реализованы

**Проблемы:**
1. Дерево не имеет явной вертикальной структуры — `tier`/`level` не используются как координаты в layout
2. Связи не различаются по типу — `AbilityEdge.type` существует, но не используется для вертикальных/диагональных/горизонтальных
3. Нет ограничений на количество связей — можно связать любой узел с любым
4. Интеграция не влияет на систему — состояние `integrated` есть, но не меняет поведение системы

**Рекомендации:**
1. Реализовать вертикальные уровни как координаты Y в layout (использовать `tier`/`level` для позиционирования)
2. Добавить типы связей в `AbilityEdge.type` (вертикальные/диагональные/горизонтальные) и использовать их в визуализации
3. Ограничить связи между узлами (валидация при создании, ограничение количества связей)
4. Реализовать логику интеграции (когда узел становится `integrated`, как это влияет на другие узлы и систему)

**Оценка:** 5/10
