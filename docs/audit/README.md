## Логика именования файлов

Все файлы документации по аудитам именуются по следующей логике:

```
<TИП_АУДИТА>_<СТАТУС>.md
```

**Где:**
- `<ТИП_АУДИТА>` — тип аудита (AUDIT_REPORT, TECH_ARCHITECTURE_AUDIT, PROJECT_MATURITY_AUDIT, SYSTEMATIC_ERROR_AUDIT, FULL_AUDIT)
- `<СТАТУС>` — статус документа (CHECKLIST, REPORT, FIXES_COMPLETE, 2025)

---

## Связанные файлы

### Чеклисты

- Используются для проведения регулярных аудитов
- Обновляются при изменении критериев оценки

### Отчеты

- Генерируются на основе чеклистов
- Содержат детальный анализ и рекомендации

## Быстрый старт

1. **Для проведения аудита:**
   - Используйте [TECH_ARCHITECTURE_AUDIT_CHECKLIST.md](./TECH_ARCHITECTURE_AUDIT_CHECKLIST.md)
   - Используйте [PROJECT_MATURITY_CHECKLIST.md](./PROJECT_MATURITY_CHECKLIST.md)

2. **Для понимания текущего состояния:**
   - Изучите [AUDIT_REPORT_2025.md](./AUDIT_REPORT_2025.md)

3. **Для работы с исправлениями:**
   - См. [AUDIT_FIXES_COMPLETE.md](./AUDIT_FIXES_COMPLETE.md)

## Обновление документации

При проведении нового аудита:

- **Создайте новый отчет** с датой в названии
- **Обновите чеклисты** при изменении критериев
- **Задокументируйте исправления** в `AUDIT_FIXES_COMPLETE.md`
