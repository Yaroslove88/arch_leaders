## Общая концепция квестов

### Назначение (из `00_UX architecture.md`)

**Квест = эксперимент в реальности**

- Квест ≠ задача
- Квест = эксперимент
- Всегда есть "почему"

**Цель:** Перевести развитие в действие.

**Состояние пользователя:** Он решает: брать или нет.

---

## Структура квеста

### Основная информация (из `docs/GAME_CONTENT.md`)

Каждый квест содержит:

1. **Основная информация:**
   - Название
   - Описание
   - Шаги выполнения
   - Критерии успеха
   - Награда (XP и прогресс по узлам)
   - Связанные узлы дерева способностей

2. **Условия разблокировки:**
   - Некоторые квесты доступны с начала игры
   - Другие требуют завершения определенных квестов
   - Некоторые требуют разблокировки определенных узлов дерева
   - Некоторые требуют активации определенных билдов

3. **Раздел "Подробнее" (теория и примеры):**
   - Теоретическое объяснение способности
   - Что это значит на практике
   - Конкретные примеры применения
   - Практические советы
   - Как интегрировать в ежедневную практику

**Важно:** Раздел "Подробнее" доступен в карточке квеста по кнопке "Подробнее". 
Это помогает понять не только что делать, но и как это делать в реальности, 
и почему это важно для развития лидерства.

## Страница деталей квеста (`/quests/[id]`)

### Структура (из `00_UX architecture.md` и `docs/USER_FLOW_DETAILED.md`)

```
[ Quest title ]
[ Hypothesis ]
[ Why this quest appeared ]
  - связи с ситуациями
  - связи с узлами
[ Steps ]
[ Evidence criteria ]
[ Possible trade-offs ]
[ CTA: Start / Log evidence ]
```

### Детальная структура (из `docs/USER_FLOW_DETAILED.md`)

**Заголовок:**
- Название квеста
- Тип (бейдж)
- Статус (бейдж)

**Описание:**
- Полное описание квеста
- Контекст и цель

**Шаги выполнения:**
Список шагов с чекбоксами:
- [✓] Шаг 1: Определите ситуацию с напряжением (выполнено)
- [ ] Шаг 2: Сделайте паузу и наблюдайте (в процессе)
- [ ] Шаг 3: Запишите наблюдения (не начато)

Каждый шаг:
- Название
- Описание
- Статус (выполнено/в процессе/не начато)
- Кнопка "Отметить выполненным"

**Критерии успеха:**
- Список критериев
- Прогресс по каждому критерию

**Связанные способности:**
- Карточки узлов дерева:
  - Название узла
  - Ветка
  - Текущий прогресс (XP)
  - Ссылка "Подробнее о способности"

**Награды:**
- XP: 100
- Skill XP: +50 к "Контейнирование"
- Прогресс по узлам

**Доказательства:**
- Список прикрепленных Evidence
- Кнопка "Добавить доказательство"

**Раздел "Подробнее" (теория и примеры):**
- Кнопка "Подробнее" / "Скрыть подробности"
- При раскрытии показывает:
  - Теоретическое объяснение способности
  - Что это значит на практике
  - Конкретные примеры применения
  - Практические советы
  - Как интегрировать в ежедневную практику
- Форматирование: Markdown с поддержкой заголовков, списков, жирного текста, курсива

**Действия:**
- Кнопки:
  - "Начать выполнение" (если не начат)
  - "Добавить доказательство"
  - "Отметить шаг выполненным"
  - "Завершить квест" (если выполнены критерии)
  - "Перевести в backlog" (если активен)

## Карточка квеста

### Структура (из `docs/USER_FLOW_DETAILED.md`)

Каждая карточка содержит:

- **Заголовок:** Название квеста
- **Тип:** Бейдж (Micro / Weekly / Story / In-person)
- **Описание:** Краткое описание (1-2 предложения)
- **Прогресс:**
  - Прогресс-бар выполнения
  - Текст: "2 из 3 шагов выполнено"
- **Связанные способности:**
  - Иконки веток
  - Названия узлов
- **Награда:**
  - XP: 100
  - Skill XP: +50 к "Контейнирование"
- **Статус:** Бейдж (Активный / Backlog / Выполнен)
- **Дедлайн:** (если есть)
- **Кнопки:**
  - "Открыть" (основная) - ссылка на детальную страницу
  - "Активировать" (если в backlog)
  - "Завершить" (если выполнены критерии)
- **Ссылка "Подробнее →"** - переход на детальную страницу

**Важно:** В карточке НЕ отображается полная теория. Теория доступна только на странице деталей квеста в раскрывающемся блоке "Подробнее".

## Визуальный стиль

### Общая эстетика (из `00_ВИЗУАЛЬНАЯ ОНТОЛОГИЯ ПРОЕКТА.md`)

**Architectural Dark Mode**

- Большие поля воздуха
- Тонкие линии
- Сетки
- Карты
- Диаграммы
- Canvas
- Фокус на структуре, не на кнопках

### Карточки (из `00_ВИЗУАЛЬНАЯ ОНТОЛОГИЯ ПРОЕКТА.md`)

- Не "плитки", а **панели**
- Лёгкая прозрачность
- Тонкая рамка
- Мягкая тень
- Градиент фона (`bg-panel-gradient`)
- Левая цветная граница (`border-l-4 border-system-focus`)

### Цветовая система (из `00_ВИЗУАЛЬНАЯ ОНТОЛОГИЯ ПРОЕКТА.md`)

**Базовая палитра:**
- Deep Graphite — #0E1116 (основа, фон)
- Architectural Blue — #0F1C2E (поле мышления)
- Cold Concrete — #1A2433 (структуры, UI-панели)

**Рабочие цвета:**
- Structural Cyan — #3A6F8F (связи, аналитика)
- Muted Teal — #2F8C8C (устойчивость, процессы)
- Steel Gray — #8A93A1 (тексты, вторичные элементы)

**Акценты:**
- Tension Amber — #F2A03D (конфликт, внимание)
- Subject Red — #C14949 (решение, граница)
- Emergence Green — #5FA38D (интеграция, зрелость)

**Принцип:** Цвет в продукте = **сигнал состояния**, а не украшение.

### Типографика (из `00_ВИЗУАЛЬНАЯ ОНТОЛОГИЯ ПРОЕКТА.md`)

- Inter / SF Pro / Manrope (инженерно-нейтральные шрифты)
- Короткие, точные тексты
- Без маркетинговых эпитетов
- Как заметки архитектора

### Форматирование теории (Markdown)

**Поддерживаемые элементы:**
- Заголовки: `#`, `##`, `###`
- Жирный текст: `**текст**`
- Курсив: `*текст*`
- Нумерованные списки: `1. пункт`
- Маркированные списки: `- пункт` или `* пункт`
- Параграфы (двойной перенос строки)

**Стили:**
- Заголовки: `font-semibold text-ui-text-main mt-6 mb-3/4`
- Параграфы: `mb-4 text-ui-text-main leading-relaxed`
- Списки: `list-disc/list-decimal ml-6 mb-4 space-y-2`
- Жирный: `font-semibold text-ui-text-main`
- Курсив: `italic text-ui-text-muted`

## Состояния квеста

### Статусы

1. **backlog** (Отложен)
   - Цвет: `system-warning` (Tension Amber)
   - Действие: "Активировать"

2. **active** (Активный)
   - Цвет: `system-growth` (Emergence Green)
   - Действие: "Завершить"

3. **done** (Завершён)
   - Цвет: `ui-text-muted` (Steel Gray)
   - Действие: Просмотр

4. **archived** (Архивирован)
   - Цвет: `ui-text-muted` (Steel Gray)
   - Действие: Просмотр

### Визуальное представление статусов

**Бейджи:**
```tsx
<span className={`px-3 py-1 rounded text-sm border ${
  quest.status === 'active'
    ? 'bg-bg-secondary border-system-growth text-system-growth'
    : quest.status === 'done'
    ? 'bg-bg-secondary border-ui-border-soft text-ui-text-muted'
    : quest.status === 'backlog'
    ? 'bg-bg-secondary border-system-warning text-system-warning'
    : 'bg-bg-secondary border-ui-border-soft text-ui-text-muted'
}`}>
```

## Типы квестов

### 1. Micro квесты (1-3 дня)

**Цель:** Быстрая практика конкретной способности в реальной ситуации

**Структура:**
- Краткое описание задачи
- 1-3 конкретных шага
- Критерии успеха
- Награда: 50-150 XP

**Бейдж:** `Micro`

### 2. Weekly квесты (неделя)

**Цель:** Систематическая практика способности в течение недели

**Структура:**
- Описание недельной практики
- 3-7 шагов
- Критерии успеха
- Награда: 150-300 XP

**Бейдж:** `Weekly`

### 3. Story квесты (2-4 недели)

**Цель:** Развитие способности через серию связанных практик

**Структура:**
- Описание истории развития
- 5-10 шагов
- Критерии успеха
- Награда: 300-500 XP

**Бейдж:** `Story`

### 4. In-person квесты (специальные события)

**Цель:** Практика в специальных условиях (коучинг, менторинг, групповые сессии)

**Структура:**
- Описание события
- Шаги подготовки, встречи, после встречи
- Критерии успеха
- Награда: 200-400 XP

**Бейдж:** `In-person`

## UX-акценты (из `00_UX architecture.md`)

- Квест ≠ задача
- Квест = эксперимент
- Всегда есть "почему"
- Не перегружать информацией
- Один главный смысл
- Минимум графиков
- Ощущение: "я в процессе, не в отчёте"

## Рекомендации по реализации

### Компоненты

1. **QuestCard** - карточка квеста для списка
2. **QuestDetail** - страница деталей квеста
3. **QuestSteps** - компонент для отображения шагов
4. **QuestCriteria** - компонент для критериев успеха
5. **QuestReward** - компонент для наград
6. **QuestTheory** - компонент для теории (раскрывающийся блок)
7. **QuestStatusBadge** - бейдж статуса
8. **QuestTypeBadge** - бейдж типа

### Обработка состояний

- Загрузка: `LoadingSpinner`
- Ошибка: `ErrorBoundary` + понятное сообщение
- Пустое состояние: иллюстрация + описание + CTA

### Доступность

- Семантические HTML теги (`<main>`, `<section>`, `<article>`)
- ARIA атрибуты для интерактивных элементов
- Управление фокусом
- Контрастность цветов (WCAG AA)
