# Логика генерации теории и примеров для квестов

> **ВАЖНО:** 
> - **Контентная база:** `QUESTS_STRUCTURED_CONTENT.md` и `QUESTS_THEORIES_MAPPING.md` являются источниками истины для всех данных квестов
> - **Методология:** Этот документ подчинен структуре из `QUEST_CONTENT_STRUCTURE.md` и примерам из `QUEST_THEORY_EXAMPLES.md`
> - **Источник теорий:** Все теоретические блоки находятся в `QUESTS_THEORIES_MAPPING.md`

## Обзор

Когда пользователь добавляет ситуацию, система анализирует её и предлагает квесты. Для каждого созданного квеста автоматически генерируется раздел "Подробнее" с теорией и примерами, который помогает пользователю понять, как выполнить квест в реальности.

**Контентная база:**
- `QUESTS_STRUCTURED_CONTENT.md` — структурированные описания всех квестов
- `QUESTS_THEORIES_MAPPING.md` — полный маппинг всех теорий

**Методология:**
- [QUEST_CONTENT_STRUCTURE.md](./QUEST_CONTENT_STRUCTURE.md) — правила структуры
- [QUEST_THEORY_EXAMPLES.md](./QUEST_THEORY_EXAMPLES.md) — примеры структуры теорий

## Процесс генерации

### 1. Пользователь добавляет ситуацию

Пользователь создает запись (entry) через форму `/entries/new`:
- Описывает ситуацию
- Указывает тип (ситуация/рефлексия/обратная связь)
- Добавляет участников и теги

### 2. Система анализирует ситуацию

После создания записи система автоматически:
- Вызывает `LLMService.analyzeSituation()` для анализа текста
- Извлекает:
  - Темы
  - Паттерны
  - Напряжения
  - Способности (ability_signals)
  - Инсайты
  - Фокус
- Создает Session с результатами анализа

### 3. Генерация квестов на основе анализа

Система вызывает `QuestGenerationService.generateQuestsFromSession()`:
- Для каждого ability_signal создается micro квест
- Для каждого focus с высоким приоритетом создается weekly квест
- Для главной темы создается story квест

### 4. Генерация теории и примеров для каждого квеста

**Для каждого создаваемого квеста:**

1. **Сбор информации о способности:**
   - Если квест связан с узлом способности (`linked_nodes`), система получает информацию об узле:
     - Название узла
     - Полное описание
     - Практическое значение
     - Примеры применения

2. **Вызов LLM для генерации теории:**
   - Система вызывает `LLMService.generateQuestTheory()`
   - Передает:
     - Информацию о квесте (название, описание, тип, шаги, критерии)
     - Информацию о способности (если есть)
   - LLM генерирует текст в формате Markdown с теорией и примерами

3. **Сохранение теории:**
   - Сгенерированный текст сохраняется в поле `criteria.theory_and_examples` квеста
   - Если генерация не удалась, квест создается без теории (можно добавить позже)

### 5. Отображение на фронтенде

Когда пользователь открывает страницу квеста (`/quests/[id]`):
- Если есть `criteria.theory_and_examples`, отображается раздел "Подробнее"
- Текст парсится из Markdown в HTML
- Пользователь видит структурированную теорию и примеры

## Структура данных

### Квест в базе данных

```typescript
{
  id: string;
  title: string;
  description: string; // Краткое описание цели (1-3 предложения)
  type: 'micro' | 'weekly' | 'story' | 'in-person';
  steps: Array<{ order: number; title?: string; description: string }>; // Шаги выполнения
  criteria: {
    type: 'count' | 'evidence' | 'streak' | 'custom';
    items?: string[]; // Критерии успеха
    description?: string; // Альтернатива items для текстового описания
    theory_and_examples?: string; // Markdown текст с теорией и примерами
  };
  linked_nodes: string[]; // ID узлов способностей
  reward?: { xp?: number; skill_xp?: number; nodes?: Record<string, number> };
  // ... другие поля
}
```

**См. [QUEST_CONTENT_STRUCTURE.md](./QUEST_CONTENT_STRUCTURE.md) для детального описания структуры всех полей.**

### Узел способности

```typescript
{
  node_id: string;
  name: string;
  full_description?: string;
  practical_meaning?: string;
  examples?: string[];
}
```

## Промпт для генерации

Промпт описан в [QUEST_THEORY_GENERATION_PROMPT.md](./QUEST_THEORY_GENERATION_PROMPT.md). Он включает:
- Контекст квеста
- Контекст способности
- Структуру раздела "Подробнее"
- Стиль написания
- Формат вывода

## Обработка ошибок

1. **Если LLM недоступен:**
   - Используется мок-генерация с базовым шаблоном
   - Квест создается без детальной теории

2. **Если генерация не удалась:**
   - Ошибка логируется
   - Квест создается без теории
   - Пользователь видит сообщение о том, что теория будет добавлена позже

3. **Если информация о способности недоступна:**
   - Генерация происходит без контекста способности
   - LLM использует только информацию о квесте

## Оптимизация

1. **Кэширование:**
   - Можно кэшировать теорию для похожих квестов
   - Можно использовать готовые описания из [QUEST_THEORY_EXAMPLES.md](./QUEST_THEORY_EXAMPLES.md) для предопределенных квестов

2. **Асинхронная генерация:**
   - Генерация теории может происходить асинхронно после создания квеста
   - Пользователь видит квест сразу, теория добавляется позже

3. **Обновление теории:**
   - Можно добавить возможность обновить теорию для существующих квестов
   - Можно улучшить теорию на основе обратной связи пользователей

## Интеграция с существующими квестами

Для квестов из каталога (`GAME_CONTENT.md`):
- Можно использовать готовые описания из [QUEST_THEORY_EXAMPLES.md](./QUEST_THEORY_EXAMPLES.md)
- Можно сгенерировать теорию с помощью LLM
- Можно комбинировать: использовать готовые описания как основу, дополнять LLM

## Мониторинг и улучшение

1. **Отслеживание качества:**
   - Собирать обратную связь пользователей о качестве теории
   - Анализировать, какие квесты чаще открывают раздел "Подробнее"

2. **Улучшение промпта:**
   - На основе обратной связи обновлять промпт
   - Добавлять примеры хороших описаний в промпт

3. **A/B тестирование:**
   - Тестировать разные версии промпта
   - Сравнивать качество сгенерированного контента
