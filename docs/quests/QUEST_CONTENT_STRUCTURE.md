# Структура контента квеста

## Принципы распределения информации

### 1. Описание (description)
**Что здесь:**
- Краткое описание цели квеста (1-3 предложения)
- Контекст: зачем это нужно
- Что пользователь получит в результате

**Чего НЕ должно быть:**
- ❌ Детальных шагов (они в отдельной секции)
- ❌ Критериев успеха (они в отдельной секции)
- ❌ Теории (она в отдельной секции)
- ❌ Наград (они в отдельной секции)

**Пример:**
```
Создайте форму (рамку, структуру), в которой другой человек может действовать из себя, а не под контролем.
```

### 2. Теория и примеры (theory_and_examples)
**Что здесь:**
- Теоретическое объяснение концепции
- Что это значит на практике
- Конкретные примеры применения
- Практические советы
- Как интегрировать в ежедневную практику
- Сравнения и различия (например, "Контроль" vs "Удержание сцены")

**Формат:**
- Markdown текст
- Поддержка заголовков, списков, жирного, курсива
- Может содержать примеры, сравнения, практические советы

**Чего НЕ должно быть:**
- ❌ Шагов выполнения (они в отдельной секции)
- ❌ Критериев (они в отдельной секции)
- ❌ Краткого описания цели (оно в описании)


### 3. Шаги выполнения (steps)
**Что здесь:**
- Конкретные действия, которые нужно выполнить
- Последовательность шагов
- Каждый шаг - одно конкретное действие

**Формат:**
- Массив объектов или строк
- Если объект: `{ title: "Название", description: "Описание", order: 1 }`
- Если строка: просто текст шага

**Чего НЕ должно быть:**
- ❌ Объяснений "почему" (это в теории)
- ❌ Критериев (они в отдельной секции)
- ❌ Длинных описаний (кратко и конкретно)

**Пример:**
```
1. Выберите ситуацию, где вы обычно контролируете
2. Создайте форму вместо контроля: рамки, структура, поддержка
3. Дайте возможность действовать в этой форме
4. Удержите форму, не вмешиваясь в действия
5. Запишите результат
```

### 4. Критерии успеха (criteria)
**Что здесь:**
- Проверяемые условия выполнения квеста
- Что должно быть сделано для завершения
- Измеримые результаты

**Формат:**
- Объект с `items: string[]` - список критериев
- Или `description: string` - текстовое описание
- Или строка - простой текст

**Чего НЕ должно быть:**
- ❌ Шагов выполнения (они в отдельной секции)
- ❌ Теории (она в отдельной секции)
- ❌ Описания цели (оно в описании)

**Пример:**
```
- Создана форма вместо контроля
- Человек действует в форме, но из себя
- Форма удержана, нет излишнего вмешательства
- Записан результат
```




### 5. Награда (reward)
**Что здесь:**
- XP за выполнение
- Прогресс по способностям (nodes)

**Когда показывать:**
- ✅ Всегда, если есть reward
- ❌ Не дублировать информацию из других секций

### 6. Связанные способности (linked_nodes)
**Что здесь:**
- Список способностей, которые развиваются через этот квест
- Только названия узлов

**Когда показывать:**
- ✅ Всегда, если есть linked_nodes
- ❌ Не дублировать в "Почему появился квест" (там показывать только если это причина появления)
### 7. Почему появился этот квест
**Что здесь:**
- Связь с ситуацией (session_id) - если квест создан из анализа
- Связь со способностями (linked_nodes) - какие способности развиваются
- Источник квеста (source) - откуда он взялся

**Когда показывать:**
- ✅ Если есть session_id - показать ссылку на ситуацию
- ✅ Если есть linked_nodes - показать связанные способности
- ✅ Если есть source - показать источник
- ❌ Если ничего нет - НЕ показывать секцию вообще
## Правила избежания дублирования

1. **Описание ≠ Шаги**
   - Описание: зачем и что получится
   - Шаги: как делать

2. **Шаги ≠ Критерии**
   - Шаги: что делать
   - Критерии: что должно быть результатом

3. **Описание ≠ Теория**
   - Описание: краткая цель
   - Теория: глубокое объяснение концепции

4. **Критерии ≠ Теория**
   - Критерии: проверяемые условия
   - Теория: объяснение и примеры

5. **Связанные способности**
   - В "Почему появился": только если это причина появления квеста
   - В "Связанные способности": всегда показывать все связанные способности

## Обработка данных

### Шаги (steps)
```typescript
// Правильная обработка
if (Array.isArray(quest.steps)) {
  quest.steps.forEach((step, index) => {
    if (typeof step === 'string') {
      // Простой текст шага
      displayStep(step, index);
    } else if (step && typeof step === 'object') {
      // Объект с title и description
      if (step.title || step.description || step.text) {
        displayStep(step.title || step.description || step.text, index);
      } else {
        // Пропустить мусор
        return;
      }
    }
  });
}
```

### Критерии (criteria)
```typescript
// Правильная обработка
if (quest.criteria) {
  if (typeof quest.criteria === 'string') {
    // Простой текст
    displayCriteria(quest.criteria);
  } else if (quest.criteria.items && Array.isArray(quest.criteria.items)) {
    // Массив критериев
    quest.criteria.items.forEach(item => {
      if (typeof item === 'string' && item.trim().length > 0) {
        displayCriterion(item);
      }
    });
  } else if (quest.criteria.description) {
    // Текстовое описание
    displayCriteria(quest.criteria.description);
  }
  // Игнорировать мусор
}
```
