## Логика именования файлов

Все файлы документации по дизайн-системе именуются по следующей логике:

```
<ТЕМА>_<ВЕРСИЯ_СТАТУС>.md
```

**Где:**
- `<ТЕМА>` — тема документа (VISUAL_ONTOLOGY, UX_ARCHITECTURE, ARCHITECTURAL_DARK, UX_UI)
- `<ВЕРСИЯ_СТАТУС>` — версия или статус (V01, COMPLETE, FINAL, AUDIT, SUMMARY)

## Связанные файлы

### Код

**Frontend стили:**
- `apps/web/src/app/globals.css` — глобальные стили с палитрой Architectural Dark

- Страницы в `apps/web/src/app/` следуют визуальной онтологии

## Быстрый старт

1. **Для понимания визуального стиля:**
   - ⚠️ **Начните с [UX_ARCHITECTURE copy.md](./UX_ARCHITECTURE%20copy.md)** — ЕДИНСТВЕННЫЙ актуальный источник по цветовой системе и визуальным принципам
   - Или [VISUAL_ONTOLOGY.md](./VISUAL_ONTOLOGY.md) (если существует, проверьте актуальность)

2. **Для работы с UX:**
   - Изучите [UX_ARCHITECTURE.md](./UX_ARCHITECTURE.md) (проверьте актуальность)

3. **Для генерации изображений:**
   - ⚠️ **Используйте [IMAGE_GENERATION_PROMPTS.md](./IMAGE_GENERATION_PROMPTS.md)** — ЕДИНСТВЕННЫЙ актуальный источник промптов
   - Все старые документы (LEADERSHIP_STYLES_IMAGE_PROMPTS.md, EMOJI_IMAGE_PROMPTS.md) в archive/ и устарели

4. **Для аудита и улучшений:**
   - См. [UX_UI_AUDIT.md](./UX_UI_AUDIT.md) и [UX_UI_IMPROVEMENTS_COMPLETE.md](./UX_UI_IMPROVEMENTS_COMPLETE.md)

## Обновление документации

При внесении изменений в дизайн-систему обновляйте соответствующую документацию:

- **Изменения в цветах/типографике** → обновить `UX_ARCHITECTURE copy.md` (единственный актуальный источник)
- **Изменения в UX структуре** → обновить `UX_ARCHITECTURE.md` (проверьте актуальность)
- **Новые промпты для изображений** → добавить в `IMAGE_GENERATION_PROMPTS.md`
- **Завершение миграции** → документы о миграции устарели, находятся в archive/
