# ЧАСТЬ I. UX-СХЕМА ДЕРЕВА СПОСОБНОСТЕЙ

## 1. Главный принцип дерева

Твоё дерево — это не “скиллы”.

Это **архитектурная карта развития субъекта.**

Поэтому:

- оно не симметричное
    
- не линейное
    
- не про “силу”, а про **уровни формы мышления**
    
- пользователь должен чувствовать:  
    👉 “я перемещаюсь в пространстве зрелости”
    

---

## 2. Пространственная модель (координаты)

Предлагаю закладывать дерево не как radial graph, а как **архитектурный ландшафт**.

### Ось Y — УРОВЕНЬ ФОРМЫ

Снизу вверх:

1. **Реактивность / Новичок**  
    — локальные решения  
    — геройство  
    — контроль  
    — симптомы
    
2. **Интеграция / Практик**  
    — сцепки  
    — правила  
    — контейнирование  
    — мышление системой
    
3. **Архитектура / Зрелость**  
    — среда  
    — формы  
    — передача субъектности  
    — исчезновение лидера
    

Это даёт естественный “вертикальный путь”.

---

### Ось X — ТИП СПОСОБНОСТЕЙ (ветки)

Не как “дерево”, а как **кварталы города**:

Слева → направо, например:

1. **Субъектность**
    
2. **Различение**
    
3. **Сборка форм**
    
4. **Контейнирование**
    
5. **Системное влияние**
    
6. **Исчезновение / Передача**
    

Каждая ветка = вертикальная зона.

---

## 3. Макро-карта дерева

Визуально:

        `▲  Архитектура / зрелость         |         |        [ Системные формы ]         |     [  передача, среда, культура  ]         |         |   [   сцепки, правила, архитектура   ]         |         | [ различение, субъектность, удержание ]         |         | [   реактивные и базовые навыки   ]         |         └──────────────────────────────────────▶            Субъект  ……………………  Архитектор`

Пользователь всегда видит:

- где “низ”
    
- где “верх”
    
- в каких “зонах” он в основном живёт
    

---

## 4. Структура ветки

Каждая ветка строится **снизу вверх**:

### Уровень 1 — Навыки реакции

(что человек делает, когда “горит”)

### Уровень 2 — Навыки различения

(что он начинает видеть)

### Уровень 3 — Архитектурные навыки

(что он начинает строить)

### Уровень 4 — Средовые навыки

(что начинает жить без него)

---

## 5. Типы узлов в UX

### ● Базовые

- плотные
    
- ближе к низу
    
- чаще активируются
    

### ◇ Архитектурные

- больше
    
- выше
    
- больше связей
    

### ⬡ Средовые

- реже
    
- шире
    
- визуально “спокойнее”
    

---

## 6. Связи

- Вертикальные → развитие внутри способности
    
- Диагональные → архитектурные сцепки
    
- Горизонтальные → перенос навыка
    

Важно:  
👉 не делать всё связанным со всем.  
Пусть будут **мосты и разрывы**.

---

## 7. UX-поведение дерева

Обязательно:

- зум как в Miro / Figma
    
- “потерянность” допустима (исследование)
    
- кнопка “вернуть меня к моему фокусу”
    
- режимы:
    
    - **My active field**
        
    - **Whole architecture**
        
    - **History view** (как дерево менялось)
        

---

## 8. UX-слои

На дереве можно включать слои:

- Активные квесты
    
- Последние evidence
    
- Напряжения
    
- Билды
    
- Недавние изменения
    

Это превращает дерево в **живую диагностическую карту.**

# 🖥 ЧАСТЬ II. НАБОР КЛЮЧЕВЫХ ЭКРАНОВ

Даю каждый экран в формате:

- 🎯 назначение
    
- 🧠 состояние пользователя
    
- 🧱 структура
    
- ✨ ключевые UX-акценты
    

---

# 🏠 1. DASHBOARD — «ПОЛЕ СЕЙЧАС»

### 🎯 Назначение

Вернуть пользователя в систему:

- что сейчас важно
    
- что меняется
    
- где его развитие
    

---

### 🧠 Состояние пользователя

Между делами. Ограниченное внимание.

---

### 🧱 Структура

`[ Header ]   - дата / уровень / текущий билд  - короткая фраза-фокус  [ Focus of the week ]  - 1 абзац  - 1 напряжение  - 1 гипотеза  [ Active quests ]   [ Last changes ]  - 3–5 карточек     - changelog highlights  [ Recent evidence / entries ]  [ Progress by branches ]  - не проценты  - а «поля активности»`

---

### ✨ Акценты

- не перегружать
    
- один главный смысл
    
- минимум графиков
    
- ощущение: “я в процессе, не в отчёте”
    

---

# 🌳 2. TREE — «АРХИТЕКТУРНАЯ КАРТА»

### 🎯 Назначение

Сделать видимым:

- как пользователь мыслит
    
- какие формы он строит
    
- где застревает
    

---

### 🧠 Состояние пользователя

Исследователь / рефлексия.

---

### 🧱 Структура

`[ Canvas — 80% экрана ]  [ Floating left panel ]   - фильтры  - режимы  - легенда состояний  [ Floating right panel ]  - карточка выбранного узла  - evidence  - связанные квесты`

---

### ✨ Акценты

- дерево “дышит”
    
- мягкий туман / глубина
    
- узлы не «кричат»
    
- акцент только на выбранном
    

---

# 📜 3. SESSION — «РАЗБОР СИТУАЦИИ»

### 🎯 Назначение

Сделать из текста → структуру.

---

### 🧠 Состояние пользователя

Он принёс реальный опыт. Он уязвим.

---

### 🧱 Структура

`[ Situation summary ]  [ Detected themes ] [ Observed patterns ] [ Key tensions ]  [ What you demonstrated ]   - способности   - способы действия  [ System reaction ]   - что изменилось в модели   - какие узлы затронуты  [ Generated quests ]`

---

### ✨ Акценты

- не «анализ»
    
- а «отражение»
    
- язык зеркала
    
- никаких оценок
    

---

# 🎯 4. QUEST — «ЭКСПЕРИМЕНТ В РЕАЛЬНОСТИ»

### 🎯 Назначение

Перевести развитие в действие.

---

### 🧠 Состояние пользователя

Он решает: брать или нет.

---

### 🧱 Структура

`[ Quest title ] [ Hypothesis ]  [ Why this quest appeared ]   - связи с ситуациями   - связи с узлами  [ Steps ]  [ Evidence criteria ]  [ Possible trade-offs ]  [ CTA: Start / Log evidence ]`

---

### ✨ Акценты

- квест ≠ задача
    
- квест = эксперимент
    
- всегда есть “почему”
    

---

# 🧠 5. ADMIN — «ОПЕРАЦИОННАЯ КОНСОЛЬ»

(в духе той спеки, что мы уже сделали)

---

### 🎯 Назначение

Управлять живой системой.

---

### 🧠 Состояние

Инженер / архитектор / исследователь.

---

### 🧱 Структура

`[ Overview ]   - здоровье системы  [ Users ]  - список  - фильтры  - быстрые метрики  [ User 360 ]  - activity  - entries  - sessions  - tree  - quests  - changelog  - debug timeline  [ Compute / Config ]  - формулы  - версии  - пересчёты  [ AI / Jobs / Audit ]`

---

### ✨ Акценты

- не “админка”
    
- а “операционная”
    
- много воздуха
    
- минимум иконок
    
- максимум структуры
