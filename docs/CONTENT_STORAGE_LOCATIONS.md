# Места хранения контента в проекте

## ⚠️ КРИТИЧЕСКАЯ ПРОБЛЕМА АРХИТЕКТУРЫ

**Текущая архитектура нарушает принцип единого источника истины:**

1. **Структура, контент и пользовательские данные смешаны** в одном месте (`TreeSemantic.data`)
2. **При обновлении seed файла система перезаписывает ВСЁ**, включая пользовательские данные
3. **Нет разделения ответственности** - данные дублируются и конфликтуют

**Результат:** При обновлении seed файла теряются:
- Русские переводы (перезаписываются английскими)
- Пользовательские данные (state, xp_current)

**Решение:** См. [ARCHITECTURE_SINGLE_SOURCE_OF_TRUTH.md](./ARCHITECTURE_SINGLE_SOURCE_OF_TRUTH.md)

**Полный аудит:** См. [FULL_ARCHITECTURE_AUDIT.md](./audit/FULL_ARCHITECTURE_AUDIT.md)

## Проблема (детали)

При исправлении багов система может перезаписывать русские переводы английскими из seed файлов. Это происходит потому, что контент хранится в нескольких местах, и система синхронизирует их из seed файлов.

## Все места хранения контента

### 1. **Seed файл (источник истины для структуры)**
- **Путь:** `packages/shared/src/seed/initial-ability-tree.json`
- **Содержит:** Структуру дерева (nodes, branches) с полями `name`, `description`
- **Используется:** 
  - При первом запуске для заполнения БД
  - При обновлении `tree_revision` для синхронизации с БД
  - При создании нового пользователя
- **⚠️ ПРОБЛЕМА:** Если здесь английские названия, они перезапишут русские в БД

### 2. **TreeSemantic.data (JSON поле в БД)**
- **Таблица:** `tree_semantic` (Prisma: `TreeSemantic`)
- **Поле:** `data` (JSON)
- **Содержит:** Полное семантическое дерево со всеми узлами и ветками
- **Обновляется из:** seed файла при `seedRevision > dbRevision` (см. `tree.service.ts:307-334`)
- **⚠️ ПРОБЛЕМА:** При обновлении seed файла система перезаписывает это поле полностью

### 3. **AbilityNode (таблица в БД)**
- **Таблица:** `ability_nodes` (Prisma: `AbilityNode`)
- **Поля:** `title`, `description`
- **Заполняется из:** seed файла при первом запуске (`tree.service.ts:90-145`)
- **Используется:** Для быстрого доступа к базовым данным узлов
- **⚠️ ПРОБЛЕМА:** Заполняется только при первом запуске, но может быть перезаписана

### 4. **node-descriptions.json (детальные описания)**
- **Путь:** `data/node-descriptions.json`
- **Содержит:** Детальные описания узлов (full_description, practical_meaning, examples, integration_levels)
- **Используется:** 
  - API endpoint `/nodes/descriptions` (`nodes.service.ts`)
  - Фронтенд для отображения детальной информации
- **✅ ХОРОШО:** Отдельный файл, не перезаписывается автоматически

### 5. **node-translations.ts (переводы на фронтенде)**
- **Путь:** `apps/web/src/lib/node-translations.ts`
- **Содержит:** Статический маппинг `node_id -> русское название`
- **Используется:** Фронтенд как fallback, если API возвращает английские названия
- **✅ ХОРОШО:** Не перезаписывается автоматически, но требует ручного обновления

### 6. **quest-templates.json (квесты)**
- **Путь:** `data/quest-templates.json`
- **Содержит:** Шаблоны квестов
- **Используется:** При создании пользователя (`user-initialization.service.ts:68-149`)

### 7. **interactive-cases.json (кейсы)**
- **Путь:** `data/interactive-cases.json`
- **Содержит:** Интерактивные кейсы
- **Используется:** API для загрузки кейсов

### 8. **builds.json (стили лидерства)**
- **Путь:** `data/builds.json`
- **Содержит:** Стили лидерства (builds)
- **Используется:** API для загрузки стилей

## Решение проблемы

### Вариант 1: Обновить seed файл русскими переводами
- Обновить `packages/shared/src/seed/initial-ability-tree.json` с русскими названиями
- Убедиться, что все узлы имеют русские `name` и `description`

### Вариант 2: Отключить автоматическое обновление из seed
- Изменить логику в `tree.service.ts`, чтобы не перезаписывать существующие данные
- Использовать seed только для создания новых записей

### Вариант 3: Использовать node-descriptions.json как источник истины
- Изменить логику, чтобы названия брались из `node-descriptions.json`, а не из seed
- Seed файл использовать только для структуры (node_id, branch_id, tier, etc.)

### Вариант 4: Создать миграцию для обновления переводов
- Создать скрипт, который обновит все существующие записи в БД русскими переводами
- Запускать после обновления seed файла

## Найденные проблемы

### Английские названия в seed файле

В `packages/shared/src/seed/initial-ability-tree.json` найдены узлы с английскими названиями:

1. **node_shared_leadership** (строка 439):
   - ❌ `"name": "Shared Leadership"`
   - ✅ Должно быть: `"name": "Распределённое лидерство"`

2. **node_feedforward** (строка 534):
   - ❌ `"name": "Feedforward"`
   - ✅ Должно быть: `"name": "Обратная связь в будущее"`

3. **node_mirror_holder** (строка 566):
   - ❌ `"name": "Window Gazer vs Mirror Holder"`
   - ✅ Должно быть: `"name": "Смотрящий в окно vs Держащий зеркало"`

4. **node_vertical_development** (строка 645):
   - ❌ `"name": "Vertical Development"`
   - ✅ Должно быть: `"name": "Вертикальное развитие"`

5. **node_ddo** (строка 661):
   - ❌ `"name": "Deliberately Developmental Organization"`
   - ✅ Должно быть: `"name": "Организация как тренажёр"`

### Почему это проблема

Когда система обновляет `TreeSemantic.data` из seed файла (при `seedRevision > dbRevision`), она **полностью перезаписывает** все данные, включая названия узлов. Если в seed файле английские названия, они перезапишут русские переводы в БД.
