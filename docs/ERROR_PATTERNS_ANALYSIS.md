# Анализ паттернов ошибок и решений

## Дата анализа: 2025-01-07
## Контекст: Исправление ошибок компиляции Next.js в проекте Leadership Architect

---

## 📊 Типизация проблем

### 1. Проблемы с JSX синтаксисом (Дублирующие закрывающие теги)

**Частота:** 4 случая  
**Файлы:**
- `apps/web/src/app/dashboard/page.tsx` - лишний `</div>`
- `apps/web/src/app/quests/page.tsx` - лишний `</button>`
- `apps/web/src/app/tree/page.tsx` - лишний `</button>`
- `apps/web/src/app/quests/[id]/page.tsx` - лишний `</div>`

**Причина:** 
- Ручное редактирование кода
- Несоответствие открывающих и закрывающих тегов
- Копирование кода без проверки структуры

**Симптомы:**
```
Error: Unexpected token `div`. Expected jsx identifier
Error: Expression expected
```

**Решение:**
- ✅ Удаление лишних закрывающих тегов
- ✅ Проверка парности всех тегов
- ✅ Использование линтера для проверки

---

### 2. Проблемы с зависимостями NestJS (Dependency Injection)

**Частота:** 1 случай  
**Файл:** `apps/api/src/sessions/sessions.module.ts`

**Причина:**
- Guard используется в контроллере, но модуль не импортирует AuthModule
- Reflector не может быть инжектирован без правильной настройки модулей

**Симптомы:**
```
TypeError: Cannot read properties of undefined (reading 'get')
TypeError: Cannot read properties of undefined (reading 'getAllAndOverride')
```

**Решение:**
- ✅ Добавление `AuthModule` в `imports` модуля, использующего guard
- ✅ Использование `getAllAndOverride` вместо `get` для безопасной работы с метаданными
- ✅ Опциональная инжекция Reflector с проверкой на undefined

---

### 3. Проблемы с дублированием кода

**Частота:** 3 случая  
**Файлы:**
- `apps/web/src/lib/api.ts` - дублированные строки после функции `getQuests`
- `apps/web/src/app/admin/page.tsx` - дублированные функции `AdminJobs` и `AdminAudit`
- `apps/web/src/app/layout.tsx` - дублированные импорты и `metadata`

**Причина:**
- Слияние кода из разных источников
- Ручное копирование без проверки существующего кода
- Отсутствие проверки перед добавлением

**Симптомы:**
```
Error: the name `X` is defined multiple times
Error: Return statement is not allowed here
```

**Решение:**
- ✅ Удаление дублированного кода
- ✅ Проверка существующих определений перед добавлением
- ✅ Использование поиска по файлу перед изменениями

---

### 4. Проблемы с Hydration (Server/Client mismatch)

**Частота:** 1 случай  
**Файл:** `apps/web/src/app/dashboard/page.tsx`

**Причина:**
- Использование `typeof window !== 'undefined'` напрямую в рендере
- Разное состояние на сервере и клиенте
- Queries с разными `enabled` состояниями

**Симптомы:**
```
Error: Hydration failed because the initial UI does not match what was rendered on the server
```

**Решение:**
- ✅ Использование `useState` и `useEffect` для клиентских данных
- ✅ Флаг `mounted` для отслеживания монтирования компонента
- ✅ Единое начальное состояние на сервере и клиенте

---

### 5. Проблемы с парсингом JSX фрагментов в Next.js SWC

**Частота:** Множественные попытки (1 реальная проблема)  
**Файл:** `apps/web/src/app/quests/[id]/page.tsx`

**Причина:**
- Next.js 14.2.35 SWC компилятор имеет проблемы с парсингом фрагментов в некоторых контекстах
- Парсер не распознает короткий синтаксис `<>` или `React.Fragment`

**Симптомы:**
```
Error: Unexpected token `div`. Expected jsx identifier
Error: Unexpected token `main`. Expected jsx identifier
Error: Expression expected
```

**Решение:**
- ✅ Использование одного корневого элемента вместо фрагмента
- ✅ Перемещение компонентов внутрь основного элемента
- ✅ Очистка кэша `.next` при проблемах парсинга

## ✅ Рабочие паттерны решений

### Паттерн 1: Систематический подход к диагностике

**Шаги:**
1. Чтение файла целиком или проблемной области
2. Поиск парности открывающих/закрывающих тегов
3. Проверка импортов и зависимостей
4. Использование линтера для валидации

**Эффективность:** ⭐⭐⭐⭐⭐

---

### Паттерн 2: Упрощение структуры JSX

**Когда применять:**
- Парсер не распознает фрагменты
- Ошибки "Unexpected token"
- Проблемы с компиляцией после изменений

**Действия:**
1. Заменить фрагменты на один корневой элемент
2. Переместить условно рендерящиеся компоненты внутрь основного элемента
3. Избегать вложенных фрагментов

**Эффективность:** ⭐⭐⭐⭐⭐

**Пример:**
```tsx
// ❌ Не работает
return (
  <>
    <Dialog />
    <main>...</main>
  </>
);

// ✅ Работает
return (
  <main>
    <Dialog />
    <div>...</div>
  </main>
);
```

### Паттерн 4: Проверка зависимостей модулей

**Когда применять:**
- Ошибки "Cannot read properties of undefined"
- Guards не работают
- Dependency Injection проблемы

**Действия:**
1. Проверить импорты модулей
2. Убедиться, что провайдеры экспортируются
3. Добавить модуль в `imports` если используется его функциональность

**Эффективность:** ⭐⭐⭐⭐⭐

**Пример:**
```typescript
// ❌ Не работает
@Module({
  imports: [PrismaModule],
  controllers: [SessionsController], // Использует JwtAuthGuard
})
export class SessionsModule {}

// ✅ Работает
@Module({
  imports: [PrismaModule, AuthModule], // Добавлен AuthModule
  controllers: [SessionsController],
})
export class SessionsModule {}
```

### Паттерн 5: Использование useState/useEffect для клиентских данных

**Когда применять:**
- Hydration errors
- Использование `window`, `localStorage`, `document`
- Разное состояние на сервере и клиенте

**Действия:**
1. Создать состояние `mounted` через `useState(false)`
2. Установить `mounted = true` в `useEffect`
3. Использовать `mounted` для условного рендеринга или запросов

**Эффективность:** ⭐⭐⭐⭐⭐

**Пример:**
```tsx
const [mounted, setMounted] = useState(false);
const [token, setToken] = useState<string | null>(null);

useEffect(() => {
  setMounted(true);
  setToken(getToken());
}, []);

const { data } = useQuery({
  queryKey: ['data'],
  queryFn: fetchData,
  enabled: !!token && mounted, // Только после монтирования
});
```

## ❌ Бессмысленные действия

### 1. Многократные попытки использовать фрагменты

**Действия:**
- Попытка 1: Использование `<>...</>`
- Попытка 2: Использование `<React.Fragment>...</React.Fragment>`
- Попытка 3: Использование `<div>...</div>` с фрагментом внутри
- Попытка 4: Условный рендеринг с фрагментом

**Проблема:** 
- Не учитывалась специфика парсера Next.js SWC
- Не проверялась документация по версии компилятора
- Повторение одного и того же подхода

**Правильное решение:** 
- Сразу использовать один корневой элемент
- Проверить версию Next.js и известные проблемы

**Урок:** Если подход не работает после 2 попыток, нужно менять стратегию.

---

### 2. Излишнее усложнение структуры

**Действия:**
- Добавление обёрток `div` когда они не нужны
- Перемещение компонентов туда-сюда
- Использование условного рендеринга когда достаточно пропа `isOpen`

**Проблема:**
- Усложнение кода без необходимости
- Больше мест для ошибок
- Сложнее отлаживать

**Правильное решение:**
- Использовать простейшую структуру
- Компоненты с пропами для управления видимостью (например, `isOpen`)

**Урок:** KISS принцип - Keep It Simple, Stupid.

---

### 3. Не проверка существующего кода перед добавлением

**Действия:**
- Добавление функций без проверки существующих
- Дублирование импортов
- Копирование кода без анализа контекста

**Проблема:**
- Дублирование кода
- Конфликты имен
- Увеличение размера бандла

**Правильное решение:**
- Всегда использовать поиск перед добавлением
- Проверять существующие определения
- Использовать линтер

**Урок:** "Measure twice, cut once" - проверяй перед изменением.

---

### 4. Игнорирование системного подхода из cursor rules

**Действия:**
- Прыжки между решениями без диагностики
- Попытки "быстрых фиксов" без понимания корневой причины
- Не использование чеклистов

**Проблема:**
- Трата времени на неэффективные решения
- Повторение ошибок
- Не систематический подход

**Правильное решение:**
- Следовать системному подходу из `.cursorrules`:
  1. Диагностика (5 минут)
  2. Быстрое решение (10 минут)
  3. Правильное решение (20 минут)
  4. Предотвращение

**Урок:** Системный подход экономит время в долгой перспективе.
